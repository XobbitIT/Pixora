# Pixora Standard Stability 1 — реалізація та межі перевірки

Дата: 18.10.2026. Збірка: `1.0.14-rc.8+local-standard-stability-1`.
База: Standard Runs 1. Пріоритет: завершення Standard без хибної паузи; дослідження фізичної якості окремо.

## 1. Вибір кольору та підказка Rust

`SelectPaletteTarget` тепер застосовується і для звичайного вибору кольору, і для двоколірного відновлення свотча. Послідовність: чинний доказ редактора → guarded click → mouse-up → guarded move у тиху точку → пасивні кадри → наявна перевірка активного кольору.

Під час короткого переходу відкладається лише автоматичне зняття кадру редактора. ESC, F6, foreground, PID/DPI/rect, перевірки координат і належності точки вікну діють. Paint-down у цьому переході заборонений. Очікуються два послідовні Present; максимум шість кадрів через 100 мс, загальний термін переходу — 2 с. Невдача або перевищення терміну відпускає ввід і ставить малювання на паузу.

Тиха точка зберігається у `EditorReference.QuietParkingPoint` у фізичних координатах відносно origin клієнта. Відбір виключає Canvas, захоплені controls, no-go області, structural patches та пікселі доказу з запасом `CaptureCursor.Clearance(0,dpi)`. Якщо місця немає, нове захоплення відмовляє. Перед використанням збережена точка перевіряється повторно. Для старих references без цього поля точка розраховується з уже збереженої геометрії; це позначається `storedPoint=false`, без перезапису еталона. Захоплення нових references зберігає точку в bundle.

Застосовано наявний guarded SendInput, який повідомляє Rust про рух. Прямий SetCursorPos не додано. Виявлення невідомих накладок залишається обов’язком свіжого proof, а не припущенням, що всі controls відомі.

16 ROI, correlation 0.985, chroma 0.05, прийнятне runtime-зміщення 0 px та RGB-пороги кольору залишено без змін. Немає навчання reference на кадрі відмови.

## 2. Edge merge thickness

Поле використовує цілочисельну перевірку 1–4 до зміни Settings. `0`, `5`, `2.5`, `abc`, порожнє значення, `NaN`, `2.0` показують локалізовану помилку біля поля; останнє чинне значення залишається. Межі 1 і 4 приймаються. Модальне вікно під час цього редагування не відкривається.

На читанні конфігу некоректне числове значення округлюється round-to-even та обмежується 1–4; непридатний текст/null замінюється на 2. Повертається `SettingsLoadWarning`, UI показує попередження, журнал отримує `settings_value_repaired` з оригіналом і заміною. Читання не переписує вихідний файл; наступне звичайне збереження запише виправлене значення. Міграція не змінює явний прапорець edge_merge. Пряма `Settings.Validate` далі відхиляє неправильні значення — помилки програміста не маскуються.

## 3. Standard: що з якістю

Причина нерівності поки не встановлена. В останньому відео три вертикалі мали змінну ширину, max residual від власної прямої приблизно 0.757 / 0.875 / 1.009 px. Це діагностичні виміри стисненого відео, не RGB-сертифікація. Повної траси фактичного курсора цього запуску немає.

У цій збірці **не змінено** емітер Standard, щільність, напрямки/порядок плану, target, палітру чи затримки штрихів. На чотирьох зафіксованих входах replay отримав ідентичні target/preview/PlanIdentity, усі центральні шляхи та запитані витримки. Для того самого замороженого набору команд sequence hash також ідентичний. Це зберігає попередню оптимізацію; не є доказом однакового фізичного сліду чи заміром загального live-часу. Нові свіжі перевірки після кольору мають власну невелику витрату часу.

Не застосовувалися .996, 1.0037, довільні offsets, підвищення витримок або автоматичне увімкнення Shift. Adaptive не змінювався.

## 4. Внутрішній evidence-режим

Додано явний CLI-вхід для розробника; START його не запускає, нових кнопок у звичайному UI немає. Реальний ввід агент у цьому етапі не запускав.

Frozen protocol: 5 позицій × H/V × суцільний/20 сегментів × 3 блоки = **60 обов’язкових samples**. Довжина 400 px, сегменти по 20 px зі спільною точкою стику; Size3 round, identity, Safe (Pitch1/Batch1), frame20ms, seed18102026. Однакові позиції повторюються у трьох блоках; порядок усередині блоків перемішаний наперед. Мінімальний Canvas 660×660; виділення не змінюється.

Задано до збору: observable maxRGB(before,after)>80, центр поперечного перерізу як середина його крайніх пікселів, власна OLS-пряма, max і P95 nearest-rank residual, min/max width, пропущені та розірвані перерізи. Це метрики без production PASS чи нового acceptance threshold.

Зберігаються native кадри background/before/after, before/after кожного сегмента, GetCursorPos після кожної одноточкової команди та фаз held/wait/released, фактичні часові мітки, origin/DPI/window/process, колір і snapshot Settings. Native PNG читаються без ліміту preview 2048 px та без масштабування. Зміна курсора, помилка API, фокус/інструмент/геометрія, шум baseline >RGB12 або збій кадру/запису роблять sample INCOMPLETE. Відмова не пропускається й не перезапускається. Програма не очищає полотно автоматично.

Перший чистий стан — явна передумова оператора. Наступні samples порівнюються з його збереженим native baseline. Кожен sample запускається окремо після ручного очищення; незавершений попередній sample забороняє продовження серії. Hash протоколу, Settings та App/Core assemblies фіксуються до першого збору. Зібрані 60 samples означають DATA_COLLECTED, а не фізичний PASS. Зараз зібрано **0/60**.

Safe потрібен, щоб читати кожен крок, а не лише останню координату пакета. Додаткові читання й знімки впливають на час; ця серія не кваліфікує швидкість Max Speed. Вона також не відокремлює всі варіанти H1 одним запуском. H2 потребуватиме окремого held-out; H3 не означає можливість змінювати внутрішній renderer Rust — допустима лише обґрунтована зміна способу вводу/проєкції Pixora після підтвердження.

## 5. Перевірки й докази

- Core: 597 PASS; повний WPF: 178 PASS, включно з 84-layout DPI matrix. Збірки без warnings/errors; окремо повторено нові targeted cases.
- Fake transaction: 50 послідовних виборів кольору, два чистих кадри, відмови до кліку/під час кліку/паркування/очікування, deadline і змінена геометрія.
- Recorded replay: raw RGBA кадру 18:22:34 лишається FAIL. Після **синтетичного** відновлення тільки ROI5 з immutable reference strict detector дає Present. Шість змін config rect ±1/2/3 px далі відхиляються. Це тест логіки, не живий кадр після зникнення підказки.
- Evidence runner: dirty baseline та prepare failure дають zero paint; draw/capture interruption — INCOMPLETE; кожен emitted Safe step має cursor sample; native loader зберігає 2560 px без ресемплінгу.
- UI: негативні значення та межі перевірено українською, англійською й російською. Нові звичайні повідомлення додано до всіх семи мов.

Пакет має `inGameTest=false`, `physicalQualityCertified=false`. Git commit/push не виконувалися. Фізичну нерівність Standard не оголошуємо виправленою; наступне причинне виправлення залежить від вимірів, а не від зелених офлайн-тестів.

## 6. Службовий запуск evidence (не звичайне малювання)

Закрити іншу Pixora. Після чинної підготовки у Standard:

```
Pixora.exe --standard-quality-evidence init C:\Evidence\new-series
Pixora.exe --standard-quality-evidence sample C:\Evidence\new-series 0
```

`init` лише створює файли. `sample` через 5 с перевіряє, що Rust уже активний; фокус не перехоплює, редактор не відкриває, полотно не чистить. Індекс 0..59 виконується строго за планом, по одному за виклик. Після INCOMPLETE створюється нова серія; переписати sample не дозволено. Пакет для звичайного тесту запускається просто `Pixora.exe`, без цих параметрів.
