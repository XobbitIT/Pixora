# Живий тест RC6 (виконує користувач)

1. Розпакувати весь новий ZIP. Перевірити заголовок 1.0.14-rc.6 (local-rc6-structure).
2. На чистому полотні Rust вручну встановити Interval0.01/Opacity1.00. Почати зі Standard, палітра, невеликий тестовий малюнок.
3. Натиснути підготовку. Повторно захопити Canvas: старий sparse reference не стає новим еталоном автоматично. Усі вибори робляться з одного замороженого кадру.
4. Після підготовки очистити крапки/лінії. Перевірити прев'ю, запустити. Очікування: жодних тихих змін кольорів/деталей; runtime-пауза має причину, не зелене «Усе готово».
5. F6, повернення фокуса, згорнення/відкриття редактора перевіряти окремо. Зміна геометрії повинна блокувати ввід до повторного захоплення. Не тиснути багато разів F6, якщо показано вимогу нового захоплення.
6. Повторити Standard з HEX. Target при однакових параметрах зображення має лишатися тим самим після переходу між режимами.
7. Окремо перевірити явний edge merge ON: до START видно X%/Y регіонів і змінене прев'ю. Повернути OFF для порівняння якості.
8. Adaptive: спочатку один великий Size (15 або20) та базовий3 на чистому полотні. Нові профілі — H/V32px із незалежною позицією. Непідтверджений напрямок не повинен малювати. Обмежений маршрут не є доказом усіх швидкостей/довжин.
9. Після невдалих проб, START/cancel і повторного відкриття зберегти експорт діагностики. Він має config-history snapshots, save IDs, stroke PNG/JSON і target identity. Старі маски не повинні зникнути без запису причини.

Порівнювати Standard/Adaptive на тому самому target, палітрі, detail і геометрії. Записати Active/Motion/Colors/Service/Pause окремо; спочатку оцінити якість. Швидкість, профілі та новий proof редактора RC6 ще не підтверджені живим тестом.
