# Pixora — готовність до Steam і підтримка

Оновлено: 21.10.2026. **Статус: NOT READY.** Фізична якість Standard та подальша кваліфікація Adaptive відкриті. Пріоритет поточної роботи — [PROJECT_STATE.md](PROJECT_STATE.md).

## Умови готовності

- [ ] Standard відтворює узгоджені тестові зображення з прийнятим контрактом фізичної якості: деталі, колір, положення/ширина H/V ліній, caps, стики та накладання. [Проєкт v1](docs/quality/PHYSICAL_QUALITY_CONTRACT.md) має запропоновані межі; заморожування політик і незалежне приймання ще не виконані. Команди completed не є Physical-quality PASS.
- [ ] Підготовка → START проходить одним робочим потоком; збереження/відновлення та STOP/PAUSE/RESUME перевірені для точного релізного пакета. Незнайомий tool, геометрія або недоступний cursor/capture безпечно зупиняють ввід.
- [ ] Усі заявлені режими, форми й Size мають відповідний рівень доказу. Непідтверджені можливості позначені експериментальними й не рекламуються як готові.
- [ ] Пройдено [TEST_MATRIX.md](TEST_MATRIX.md); збережені конкретні build/test/package receipts. Відомі блокувальні дефекти закриті, обмеження явно описані.
- [ ] Release Windows x64 перевірений після розпакування/встановлення в ізольованому Windows-середовищі: запуск, залежності, settings, recovery, DPI/layout, підтримувані мови. Обмеження середовища записані.
- [ ] Є виміряні вимоги CPU/RAM і репрезентативні показники продуктивності/якості. Час одного ПК не видається за універсальну гарантію.

## Пакет, встановлення і відкат

- [ ] Окремий чистий user/depot content: Pixora.exe, необхідні залежності, ліцензійні повідомлення, актуальна коротка інструкція. Не включати Source, tests, конфігурацію/логи користувачів, raw evidence, frozen калібрування, `Frontier_Pair` чи `Verification` з діагностичного runtime.
- [ ] Version, App/Core hashes, source fingerprint і manifest узгоджені; перевіряються саме поширювані DLL. Перевірка архіву не замінює запуск програми.
- [ ] Міграція settings/checkpoints/profiles перевірена зі збереженою копією попереднього стану. Описано сумісність відкату; старі дані не підміняються чи стираються задля успіху нового запуску.
- [ ] Є перевірений попередній пакет і конкретний спосіб повернення. Збірка-кандидат не замінює стабільну версію до приймання.

## Матеріали Steam

Наявні [README_UA.md](release/Steam/README_UA.md), [app_build.vdf.template](release/Steam/app_build.vdf.template) та [Store_Copy.md](release/Steam/Store_Copy.md) — історичні заготовки beta.53. Їхня наявність не означає поточної готовності чи виконаної публікації.

- [ ] Перевірити актуальні офіційні вимоги Steamworks перед заповненням матеріалів/завантаженням; не вважати старі посилання перевіреною сьогодні специфікацією.
- [ ] Підтвердити справжні AppID/DepotID, реквізити, контакти підтримки, права на матеріали й умови розповсюдження залежностей. Не вигадувати значення й не зберігати credentials у джерелах/пакетах.
- [ ] Опис, зображення та заявлені мови відповідають фактично перевіреній поведінці. Не обіцяти сертифікацію якості, сумісність або швидкість без доказу.
- [ ] Підготувати точний content і перевірити preview/локальний manifest до зовнішньої публікації. Історичний шаблон має `Preview=1` і placeholders; це не виконаний upload.
- [ ] Реальні upload/SetLive/публікація виконуються як окремі явно авторизовані дії після підготовки конкретного перевірного пакета. Поточне завдання документації їх не запускає.

## Після випуску

Для кожного інциденту зберігати версію, відтворення, діагностику без зайвих приватних даних і regression case. Порядок: критичний дефект → стабільність → якість → продуктивність → UX. Виправлення проходить релевантну матрицю й перевірку готового пакета; після нього оновлюється PROJECT_STATE. Не обіцяти фоновий моніторинг чи автоматичну підтримку без реально налаштованого механізму.
