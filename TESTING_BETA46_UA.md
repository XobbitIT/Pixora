# Pixora 1.0.14-beta.46 — короткий живий тест ноутбука

1. Закрий стару Pixora. Розпакуй beta.46 в окрему папку й перевір версію у заголовку. Наявну конфігурацію можна зберегти; якщо роздільна здатність або масштаб Rust змінилися, повтори захоплення.
2. Відкрий малювання в Rust. Залиш гру на передньому плані протягом перевірки. Не змінюй затримки: спершу потрібно перевірити новий транспорт із тими самими параметрами.
3. Виконай окремий тест HEX тричі. Кожен запуск має підтвердити FF3333, 12AC5F і 0397E2. Вставлене значення без підтвердженого читання не рахується успіхом. Зверни увагу, чи зникла пауза перед помилкою буфера.
4. Виконай окрему перевірку Controls. Запиши, на чому зупинилася: Size, Interval чи Opacity. Коли число прочитане, але смуга відхилена, відкрий `%LOCALAPPDATA%\Pixora\controls-diagnostics` і збережи нову папку `size-*` / `interval-*` / `opacity-*` з `slider.png` та `diagnosis.json`. Назва починається з часу UTC, потім містить тип контролю.
5. Лише після успішних HEX і Controls відкалібруй Size 3. Потім перевір Size 1 окремо. Невдалий контраст або solid core Size 1 не обходиться успішним копіюванням числа.
6. Якщо Size 3 підтверджений, використай його для Four Blocks; перевір чотири суцільні блоки, правильні кольори й завершення. Для Adaptive потрібен окремий підтверджений Size 1.

Для аналізу надішли свіжий `session-csharp.jsonl`, `config-csharp.json` та нові папки `controls-diagnostics`, якщо вони з'явилися. Корисні події: `owner_created`, `owner_message` (775 = WM_DESTROYCLIPBOARD), `copy_empty_pending`, `control_readback`, `slider_read_failed`, `slider_check`. Відсутність `owner_message` сама по собі не означає помилку.

346 Core / 107 WPF перевірок оцінюють код і транспорт. Цей пакет ще потребує живого підтвердження на ноутбуці.
