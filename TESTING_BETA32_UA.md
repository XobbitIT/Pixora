# Pixora 1.0.14-beta.32 — короткий тест у Rust

## Простий режим: головний тест

1. Закрий стару Pixora. Розпакуй весь новий архів у окрему папку та запусти Pixora.exe. У шапці має бути beta.32. Для Windows x64 portable-пакет містить .NET Runtime.
2. Відкрий редактор картини Rust на чистому тестовому полотні. Вибери суцільний квадратний пензель (4-й), впиши **розмір 1, інтервал 0.01, прозорість 1**. Простий режим не встановлює ці значення автоматично.
3. У Pixora відкрий зображення з чотирма суцільними блоками або перетягни PNG у сторінку малювання. Має з'явитися оригінал і зрозумілий наступний крок, без вимоги калібрувати пензель.
4. Залиш «Палітра Rust». Натисни «Вибрати полотно й кольори»: спочатку виділи внутрішню область полотна без рамки, потім усю палітру 4×16. Якщо скасувати друге виділення, попередні області мають зберегтися.
5. Натисни «Малювати». Не запускай Speed Probe, калібрування Size чи аудит. Програма повинна застосовувати кольори та малювати без кліків по незахоплених повзунках. Перевір, чи суцільні блоки заповнилися, чи немає прогалин, зайвих ліній та виходу за полотно. Збережи скриншот; 100% команд ще не доводить якість покриття.
6. Повтори на чистому полотні в HEX: відкрий поле HEX у грі, обери «HEX» у Pixora та повтори два виділення (полотно / поле із шістьма цифрами). Після перемикання меню Rust перевір ручні значення пензля з пункту 2. Окремий тест трьох кольорів та захоплення HEX-повзунків у простому режимі не потрібні. Колір має зчитуватися правильно перед малюванням.
7. Під час нового малювання натисни F6, потім віднови. Якщо змінював пензель у грі під час паузи, поверни квадрат / 1 / 0.01 / 1 до продовження. Перевір ESC. Переміщення або зміна розміру вікна Rust має вимагати нового захоплення, а не продовжувати зі старими координатами.

## Інтерфейс і розширені можливості

8. На вікні 900×620 кнопка «Малювати» повинна бути видима без прокрутки. Перемкни українську / англійську: кнопки, підказки та статуси простого режиму мають перекладатися.
9. Натисни «Розширений режим». Попередні настройки adaptive, Probe й аудиту мають зберегтися. Без чинного Size 1 спроба увімкнути adaptive має пояснювати причину та залишати його вимкненим. Кнопка «Калібрувати автоматично» при неповній підготовці має відкрити захоплення з поясненням.
10. Повернися до простого режиму: невдала калібровка чи старий Probe не повинні блокувати просте малювання. Старий checkpoint іншого плану може вимагати нового запуску. Для повної перевірки виміряних маршрутів користуйся TESTING_BETA31_UA.md у репозиторії; критерії лишилися попередніми.

Для фідбеку: версія, Palette/HEX, деталізація, скриншот кінцевого полотна, відео від відкриття зображення до завершення та поточний session-csharp.jsonl з папки `%LOCALAPPDATA%/Pixora` саме того ПК, де був тест. Нового живого тесту Rust під час підготовки beta.32 не проводилось.
