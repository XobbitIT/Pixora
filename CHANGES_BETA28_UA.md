# Pixora beta.28 — незалежне калібрування Size

Нові живі спроби beta.27 від 06.10.2026 10:37 за Києвом двічі відхилили першу круглу крапку Size 1: контраст 70/255 і 69/255 при потрібних 80; в обох випадках 8 змінених пікселів. HEX 000000, Size 1, Interval 0.01 та Opacity 1 прочитані точно. На PNG крапка присутня. Причина її слабкого контрасту ще потребує живого порівняння з Square №4; згладжування/субпіксельна фаза залишаються гіпотезою. Поріг 80 не змінено.

Попередня помилка workflow: відмова однієї крапки переривала весь 1/3/10/20 batch і блокувала навіть незалежний тест уже виміряного Size 3. Тепер:

- Кожен Size — окремий набір із трьох послідовних узгоджених вимірювань. Слабкий Size відхиляється, решта вимірюється далі. Два вимірювання не створюють профіль.
- Публікуються лише повні успішні Size. Старі актуальні маски інших Size/форм зберігаються; невдалий Size не замінює свою попередню маску. Нестабільна сцена, обрізаний слід, ESC, втрата фокуса або помилка I/O переривають запуск до публікації нових профілів.
- Частковий результат показує збережені/відхилені Size та конкретний контраст. `result.json` і журнал містять відмови й список успішних профілів. Причини перекладаються після зміни мови.
- Просторове калібрування та Speed Probe потребують актуального стабільного ядра саме вибраного Size. Size 3 з власною маскою можна тестувати без Size 1. Його proof не підтверджує Size 1 і не вмикає адаптивний режим чи аудит без потрібного базового калібрування.
- Для адаптивного режиму вимога актуального Size 1 зі стабільним ядром збережена. При частковому наборі автоматичне ввімкнення адаптиву не відбувається. UI пояснює, чого бракує, замість повідомлення про нібито змінені координати.

Модель масок `command-masks-v1`, алгоритми planner/repair/audit, таймінги й методика локальних slow references v5 не змінені. Переміщення Rust, інша форма або зміна масок як і раніше роблять відповідні докази застарілими. Контрастний слід не видається за правильний колір.

Перевірки: 223 Core / 60 WPF сценаріїв. Нові регресії перевіряють збереження Size 3 при слабкому Size 1, відмову неповним/неузгодженим наборам, збереження старих масок, відсутність адаптивної готовності та незалежний proof Size 3. Конкретні результати default runtime, точних DLL і Windows CI записуються в маніфест архіву. Новий живий тест beta.28 ще потрібен.

Beta.28 усуває блокування калібрування інших Size, але фізично слабкий круглий Size 1 поки залишається відхиленим. Якщо Square 1 теж не дає підтвердженої крапки, збережи before/after/metrics — потрібна подальша робота над реальною моделлю мінімального пензля, а не зниження порога для отримання PASS.
