# Pixora 1.0.14-beta.47 — коротка підготовка й повільний ноутбук

Локальна тестова збірка. Нові зміни не відправлені в GitHub. Живий Rust не запускався; `inGameTest=false`.

## Налаштування

- Основна кнопка «Підготувати до малювання»: області Rust → кольори → керування → три незалежні вимірювання одного робочого пензля. Типовий Size 3; уже вибраний Size 10/20 зберігається. Size 1, Spatial і Speed Probe не блокують цей ланцюжок. Невдалий свіжий вимір не підтверджується старим профілем.
- Основна підготовка встановлює Precision, Opacity 1 і Stable, вимикає Adaptive, автоматичний ремонт, аудит та прискорені маршрути. Їх можна ввімкнути окремо після відповідних перевірок. У короткому проході немає прихованої спроби іншої форми пензля.
- HEX потребує шість виділень: полотно, поле HEX, форми пензля, Size, Interval, Opacity. Захоплення знарядь не потрібне; користувач обирає інструмент пензля в Rust. Прибрані кнопки захоплення верхньої панелі, Save/Cancel, цілого інтерфейсу, гумки й піпетки, які малювання не використовувало. Для палітри лишився один клік по інструменту пензля.
- Окремі дії та повний ланцюжок Spatial/Speed збережені в згорнутому блоці. Меню має один режим роботи; додаткові можливості залишаються на сторінках «Пензель» і «Тест швидкості».

## Надійність

- Налаштування → «Повільний ноутбук»: Stable, `fast_transfer=false`, 54 опитування / 3 спроби копіювання, 200 мс додаткової паузи наступної спроби, 10 спроб стабільного кадру з інтервалом 160 мс. Кожна спроба копіювання має приблизно 2,5–3 с очікування. «Звичайний ПК» повертає 24 / 3 / 50 мс та 5 / 80 мс.
- Опційне візуальне підтвердження не виконує Ctrl+C для Size/Interval/Opacity. Воно перевіряє одну й ту саму смугу та числове поле на двох знімках, використовуючи незмінний допуск положення смуги. Перед малюванням обов’язковий актуальний відбиток саме робочого Size з підтвердженим суцільним ядром. START і виконавець окремо перевіряють цю умову.
- Важливе уточнення TASK-1: відбиток не може сам довести точне текстове число Interval/Opacity. Візуальний режим підтверджує положення смуги та фізичний відбиток; UI прямо показує цю межу. Типове підтвердження числа буфером залишається доступним. HEX і далі потребує точного підтвердження кольору; цей режим не скасовує його.
- Таймінгові бюджети доступні окремо; перевіряються межі та цілі значення. Збільшення числа кадрів не змінює `CoverageAudit.Stable`.
- `control_copy_unavailable` містить координати запитаного й фактичного курсора, DPI, бюджет, кількість читань і останній безпечний текст. Записуються лише маркер або припустиме число; інший текст приховується. Збіг координат не доводить фокус текстового поля та не визначає автора очищення буфера.
