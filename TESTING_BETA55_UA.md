# Живий тест beta.55

1. Розпакуй архів у нову папку, перевір beta.55 у заголовку. Завершений малюнок збережи до тесту. Для цієї версії почни новий START, а не старий checkpoint.
2. Відкрий чисте полотно Rust. Натисни «Підготувати до малювання». У розділі «Пензель» перевір групу 2/3/5/7/10/15/20: для кожного успішного Size має бути 3/3, показаний стабільний слід і ядро. Невдалий Size не має видаляти решту. Очисти тестові відбитки.
3. За потреби окремо перевір Size 30 або 40. Size 60/100 потребують більше чистого простору. Size означає значення поля Rust; порівнюй фактично виміряний слід у px.
4. На одному зображенні та однаковому полотні порівняй звичайний Size 3 і Adaptive з максимумом 20. Незмінні кольоровий режим, кількість кольорів, деталізація, opacity і профіль руху. Перед кожним запуском очисти полотно. Запиши час без пауз, число операцій, заявлені модельні пропуски та вигляд країв. Особливо корисні герб з останнього відео й чотири кольорові блоки.
5. Повтори запуск із увімкненим перевіреним Speed Probe та тим самим параметром швидкого перенесення. Довга лінія не повинна примусово дробитися на повільні Shift-відрізки, коли звичайний рух дешевший. Короткі перевірені відрізки можуть використовувати підтверджений маршрут. Зміна Size не повинна успадковувати доказ іншого Size.
6. Перевір повороти й переходи між близькими ділянками: не повинно бути мостів через інший колір, ліній через порожній фон або довгих випадкових переходів. Увімкни аудит на чотирьох блоках: Missing/Unknown не мають ставати успіхом без перевірки.
7. Натисни F6, повернись у Rust і продовж. Перевір STOP, новий START і RESUME на checkpoint, створеному саме beta.55. Перевірка після смерті необов'язкова: у твоєму beta.54 відео цей сценарій уже працював.

Надішли відео, `session-csharp.jsonl`, `config-csharp.json` і папку діагностики невдалого етапу. Для порівняння часу зазнач: зображення, режим кольорів, Size, Adaptive, Speed Probe, швидке перенесення, початок/кінець і паузи.

Поки ці сценарії не виконані, швидкість і результат beta.55 у грі не підтверджені. В архіві немає особистих журналів чи конфігурації.
