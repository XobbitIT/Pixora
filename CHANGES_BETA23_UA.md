# Pixora 1.0.14-beta.23 — діагностика траєкторії Speed Probe

У діагностиці швидких проб і перевірок запасу видно переважне зміщення, діапазон однозначних зміщень, кількість переходів між сусідніми однозначними перерізами та найбільший стрибок. Дані також зберігаються в `run.json`, `metrics.json` і `session-csharp.jsonl`.

Це опис просторового положення підтвердженого ядра на знімку, а не вимір траєкторії системного курсора в часі. Якщо повне ядро підходить до кількох центрів, переріз позначений неоднозначним. Через такий переріз або прогалину переходи не рахуються. За однакової максимальної частоти показуються всі переважні зміщення; єдине не вигадується. Якщо немає сусідніх однозначних перерізів, UI показує «—», а не «стабільно, 0 переходів». При зміні сцени траєкторія недоступна.

Нова статистика не бере участі в PASS/FAIL. Зигзаг із повним підтвердженим ядром у кожному перерізі може пройти чинний критерій, але його переходи будуть видимі. Рішення про додатковий критерій стабільності потребує живих даних. Колір, допуск, заморожений діапазон, потрібна ширина ядра, перевірка сцени та правила аудиту залишаються такими, як у beta.22.

Ревізія `probe-spatial-envelope-v4`, контексти калібрування, таймер, затримки вводу, групування кольорів, планувальник, ETA й checkpoint не змінені. Сумісні докази beta.22 не скидаються через цю статистику. Старі звіти відкриваються з повідомленням про відсутню діагностику; дані не домальовуються. Якщо з beta.21 ще не виконано нового просторового калібрування й Speed Probe, їх усе одно потрібно пройти.

Windows CI уже перевіряв Core/WPF. Тепер додано запис `dotnet --info`, звірку SHA-256 двох головних DLL після публікації, WPF-перевірку на опублікованих DLL і завантаження діагностики навіть при помилці. Зміни workflow локальні: запуск на GitHub не виконаний, проблема CLR/Roslyn не позначається закритою. Локальний build-workaround не доданий у CI або runtime продукту.

Перевірки: стабільна лінія, один перехід, частий зигзаг зі збереженим PASS, неоднозначний широкий core, прогалина без з’єднання сусідів, зміна сцени, JSON round-trip, старі звіти та видимість нових показників українською/англійською. Локальна перевірка DLL не є новим тестом у Rust.
