# Pixora 1.0.14-beta.45 — копіювання числових полів на ноутбуці

Лог ноутбука beta.44 за 07.10.2026, 22:04–22:15, не містить виміряних відбитків пензля. Чотири читання Size 1 підтвердили число 1.00; наступний Interval 0.01 щоразу залишав маркер замість відповіді Rust. Частина HEX-перевірок успішна, частина має ту саму відсутню відповідь. Пізні зміни буфера з невідомим власником зупиняли наступний ввід; наприкінці також зафіксована втрата фокусу. Причину затримки або відсутнього копіювання самі логи не встановлюють.

## Виправлення

- Numeric і HEX readback залишають початкове швидке читання. Якщо копіювання не завершилося, вони опитують буфер до однієї додаткової секунди перед новим виділенням поля або записом маркера. Три спроби залишаються обмеженими; ESC, скасування й втрата фокусу переривають очікування.
- Кліки по інтерфейсу Rust використовують guarded SendInput, як транспорт малювання й паркування курсора. У лог додаються запитана й фактична позиції виділення та DPI. Це допоможе відрізнити помилку позиції від відсутнього копіювання.
- Якщо три спроби не отримали число, Pixora повідомляє конкретне поле Size / Interval / Opacity і припиняє операцію перед новим вставленням. Журнал містить `control_copy_unavailable`; повторне налаштування потрібне для зазначеного поля.
- Втрата фокусу більше не показує користувачу сирий тип `Painter+InputInterrupted`. Повідомлення пояснює повернення у Rust, повтор перевірки та F6 для продовження малювання. Нові повідомлення перекладені українською й англійською.

## Межі й перевірки

Захист буфера не послаблений: сторонні або невідомі пізні дані не дозволяють наступний запис і зберігаються під час прибирання. Правильність числа й положення смуги все ще потрібна. Контраст 80, RGB tolerance 12, перетин масок пензля, критерії Speed Probe, planner і аудит не змінені. Beta.45 не оголошує Size 1 або ноутбук перевіреними.
