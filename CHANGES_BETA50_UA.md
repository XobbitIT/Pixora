# Pixora 1.0.14-beta.50 — палітра, синхронні налаштування і комбіновані пензлі

Офлайн-перевірена збірка після beta.49. Pixora.exe та живий Rust для її перевірки не запускалися. Код опубліковано в [PR #2](https://github.com/XobbitIT/Pixora/pull/2); GitHub Actions збирає portable-архів з коміту. Раніше надісланий локальний ZIP зберігає початковий маніфест збірки до коміту.

## Що виправлено

- На сторінці «Малювання» є окремі кнопки **Палітра Rust** та **Прямий HEX**. Вибір зберігається. Для кожного режиму потрібне власне захоплення його керування в Rust; захоплення HEX не підтверджує палітру.
- Числові зміни застосовуються й оновлюють готовність одразу, без очікування втрати фокуса. Спільний механізм синхронізує поля й перемикачі, якщо один параметр має кілька редакторів; це перевірено окремим регресійним сценарієм. Невалідні числа не зберігаються й блокують START.
- Чіп пензля показує стан робочого Size. Невдале вимірювання Size 1 не позначає підтверджений Size 3 як помилку. Чіп швидкості відповідає вибраному Size тесту.
- Adaptive більше не потребує саме Size 1: достатньо актуального вимірювання зі стабільним ядром у вибраному діапазоні. Комбінуються лише підтверджені Size/форми. Типовий Size — 3; Size 1 повернено як окремий вибір, який потребує власного підтвердження.
- Біля заблокованих кнопок просторового калібрування та Speed Probe є причина. Профіль не має таймера придатності: зміни полотна, режиму кольору, форми чи вимірювань роблять відповідний доказ застарілим.

## Ядро планування змінене

Звичайне Precision-малювання з виміряним пензлем тепер враховує його фізичне зміщення і всю можливу маску. Раніше команди звичайного Size 3 ставилися у координати потрібних пікселів без такого обмеження. У поточних вимірюваннях Size 3 має можливий слід 17 × 18 px і зміщене ядро 6 × 3 px; значення «3» у Rust не означає слід рівно 3 екранні пікселі.

Планер допускає команду лише там, де виміряна можлива маска залишається в одній очікуваній кольоровій області. Гарантовану частину моделі покриття визначає solid-mask, а не safety radius. Великі суцільні області отримують широкий пензель; залишки — найменший придатний виміряний. Безпечні близькі команди об'єднуються лише після перевірки всього шляху. Кожний колір завершується перед переходом до наступного.

Якщо жоден підтверджений пензель не поміщається у вузьку область, план не додає туди небезпечну команду. Перед START показується кількість пікселів без команд і кнопка з рожевою маскою. **Це модель плану, а не перевірка фактичного покриття у Rust.** Виміряний Size 1 або менша кількість кольорів можуть зменшити такі області. Якщо весь план порожній, START заблокований з поясненням.

Аудит і ремонт можуть використовувати найменший придатний виміряний Size, зокрема 3. Unknown не є цілями ремонту. Після ремонту відновлюються робочі форма й Size. Для старих калібрувань без масок лишається попередній шлях; новий захист за масками потребує актуальних вимірювань.

## Що не послаблено

Контраст **80**, RGB tolerance **12**, перетин масок трьох вимірювань, критерії локального кольору, Speed Probe, просторової перевірки і CoverageAudit не змінені. Слабкий Size 1 залишається відхиленим. Формули затримок вводу і rolling ETA з beta.49 не змінені. Змінився саме план команд і спосіб доступу до налаштувань.

Ідентичність плану оновлена. **Не продовжуй RESUME beta.49: очисти полотно й почни новий START.**

## Перевірка і практичні межі

388 Core і 125 WPF офлайн-перевірок; Release без попереджень і помилок. У пакет входить геометрія реальних вимірювань Size 3/10/20 для регресійних тестів, без конфігурації користувача та журналів сеансу.

На синтетичному двоколірному полотні 400 × 320 з цими масками план має **408 операцій замість 640**, але **11 202 px без гарантованих команд**. Це порівняння планів, не результат живого малювання і не обіцянка такого прискорення фотографій. Зменшення часу та відсутність перефарбовування в грі ще треба перевірити.

Переглянутий beta.49 сеанс з 95 743 операціями був перерваний після 41 188: завершеного результату для нього немає. 59 HEX-підтверджень у переглянутих подіях успішні. Це підтримує перевірку геометрії пензля як причини перефарбовування, але не доводить її як єдину можливу причину.
