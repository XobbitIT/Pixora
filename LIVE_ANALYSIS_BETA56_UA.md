# Аналіз надісланих тестів beta.55

## Що підтверджено

Надіслані журнали іншого пристрою й локальні журнали цього ПК аналізувалися окремо. На іншому пристрої захоплено 64 комірки палітри. У 170 перевірках колір цільової комірки збігався з очікуваним. Це перевірка комірки перед вибором, а не підтвердження RGB фарби на полотні. Створення HEX-кольорів поза захопленою палітрою в цих запусках не виявлено.

BVB завершився: 7856 операцій, 629,66 с активного часу. План містив десять кольорів, але лише чотири мали безпечні штрихи. Шість порожніх груп усе одно спричиняли вибір кольору. Beta.56 прибирає ці перемикання. Аналогічно для FCB у повторному розрахунку 32 очікуваних групи перетворюються на вісім груп із командами. Значна частина додаткових відтінків походить із країв вхідного зображення; це наявні комірки палітри, а не нові RGB.

Сірі прогалини на FCB узгоджуються з обмеженням плану: для 182885 із 613872 цільових px не знайдені безпечні команди за виміряними масками. Для BVB таких px 172967. Beta.56 ці пропуски не видає за заливку й не додає команд, що можуть перетнути межу іншого кольору.

У локальному відео видно широкі й дрібні проходи одного синього кольору. Останній локальний запуск у HEX/Adaptive мав 6851 операцію й зупинився на паузі після 1709; завершення цього запуску в журналі немає. Не можна порівнювати його незавершений реальний час із завершеним BVB іншого пристрою.

## Повторний розрахунок beta.55 → beta.56

Таблиця використовує надіслані BVB/FCB та раніше збережений тризуб із поточними знімками конфігурації відповідного пристрою. Це офлайн-розрахунок із виміряними масками, не повторне малювання в Rust. Хеш маски покриття збігся в усіх восьми порівняннях.

| Інший пристрій / BVB | Звичайний | 7856 → 7856 | 10 → 4 | 556,02 → 553,26 с |
| Інший пристрій / BVB | Adaptive | 7856 → 7856 | 10 → 4 | 556,02 → 553,26 с |
| Інший пристрій / FCB | Звичайний | 8450 → 8450 | 32 → 8 | 601,26 → 590,22 с |
| Інший пристрій / FCB | Adaptive | 8071 → 8070 | 32 → 8 | 582,20 → 571,09 с |
| Цей ПК / BVB | Звичайний | 9216 → 9216 | 96 → 7 | 769,77 → 585,54 с |
| Цей ПК / BVB | Adaptive | 13078 → 10091 | 96 → 7 | 1048,52 → 682,06 с |

Для локального тризуба прибрано 1473 штрихи, скорочено 1066. Усунення надлишкових проходів саме по собі змінює модель 496,60 → 406,74 с; решта економії походить із пропуску порожніх кольорових груп. Сума нового покриття за всіма Size — та сама, 365482 px. Часткові перекриття залишаються: вони потрібні для безперервної заливки та досягнення залишкових ділянок.

## Що ще не гаразд

- Фактичне повне покриття в грі не підтверджене. Частина запусків завершилася без аудиту. Інші зупинялися через Unknown на низькоконтрастному білому; це не доказ відсутності фарби.
- Звичайний режим ще може бути швидшим за Adaptive: у локальному тризубі він покриває менше модельних px (354729 проти 365482). Саме великий Size не гарантує великого стабільного ядра чи виграшу часу.
- Size 3 має значне необхідне перекриття на конфігурації іншого пристрою. Там усунення повністю зайвих штрихів не дає великого прискорення.
- Офлайн-ETA не дорівнює реальному часу: BVB фактично тривав 629,66 с проти моделі beta.55 556,02 с. Для beta.56 потрібен новий живий прогін; точність ETA ще не підтверджена.
- Груповий Speed Probe може відхилити окремий Size або вимагати більше чистого місця. Пороги й незалежні повільні контролі залишаються суворими.

Новий реліз перевіряється збіркою, Core/WPF headless та повторним запуском тестів на DLL готового пакета. Нова програма в Rust тут не запускалася. Живий тест користувача описаний у [TESTING_BETA56_UA.md](TESTING_BETA56_UA.md).
