# Pixora 1.0.14-beta.35 — живий тест Speed Probe

Розпакуй весь portable-архів у нову папку, запусти Pixora.exe. Якщо Square №4 / Size 1 вже виміряний і стан пензля зелений, повторно вимірювати його не потрібно. Старі просторові й швидкісні результати застаріли через новий протокол.

1. Відкрий той самий редактор Rust і чисте полотно, залиш HEX/палітру та масштаб гри відповідними захопленню Pixora.
2. У «Пензель і швидкість» вибери Square №4, Size 1. Виконай просторове калібрування: потрібні всі шість підтверджених ліній.
3. Очисти полотно. Запусти тест швидкості. Не рухай мишу, не змінюй вікно гри чи налаштування; ESC скасовує тест.
4. Перевір, що повільний і швидкий відрізки йдуть по одній прямій, між ними є чистий проміжок. Поперечні паралельні пари з beta.34 більше не використовуються.
5. Після завершення запиши збережені маршрути, напрямок, метод і затримки. Якщо маршрути не підтверджені, відкрий діагностику: «невідповідність кольору» відрізняється від прогалин або виходу за просторову модель. FAIL не слід трактувати як успішне прискорення.
6. Якщо Size 1 має підтверджений маршрут, очисти полотно й перенеси Four Blocks, потім зображення з великими однотонними областями. Збережи відео, журнал і результат аудиту.
7. Окремо повтори просторовий і швидкісний тест для виміряного Size 3. Успішний Size 1 не підтверджує Size 3 чи інші форми.

Запиши відео від натискання тесту до фінального статусу. Для діагностики потрібні `session-csharp.jsonl`, `config-csharp.json` і остання папка `speed-probe/run-*` у `%LOCALAPPDATA%/Pixora`.

Додатково: F6/ESC і втрата фокусу мають зупиняти ввід; повернення не повинне залишати натиснутий пензель або Shift. Після тесту курсор повертається до останньої дії малювання за умови незмінного фокусу.
