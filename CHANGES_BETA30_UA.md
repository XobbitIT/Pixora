# Pixora beta.30 — перевірка напрямку кольору калібрування

У живих beta.29 знімках знайшовся білий слід RGB 226/226/226 при запитаному чорному 000000. Контраст 117 перевищував строгий поріг 80, тому лише абсолютна різниця пікселів могла помилково прийняти цей слід за фарбу. Запуск був скасований і нового профілю не опублікував. Походження світлого сліду ще не доведено.

Beta.30 додатково перевіряє напрямок зміни кожного пікселя з delta >12 від фону до запитаного кольору. Якщо очікувана різниця замала (<24 у всіх каналах), напрямок протилежний або cosine <0.5, крапка не сертифікується. Чорне затемнення, біле освітлення і ненейтральні кольори Palette підтримуються. Це консервативний захист від стороннього сліду, а не доказ точного RGB чи opacity.

Сумнівний або порожній перший знімок отримує одну додаткову перевірку після 250 ms та звичайного settling. Нового мазка немає. Зберігаються suspect-after PNG, initial/final colorCheck та recaptured. Повторний сумнівний кадр відхиляє Size. Перевірка обрізання/зміни сцени виконується до повторного знімка; ESC/фокус і помилки не приховуються. Три незалежні крапки, поріг 80, шум ≤12 та маски possible/solid залишаються строгими.

Слабкі повторювані сліди неправильного напрямку більше не отримують жовту оцінку повторюваності. Помилка кольору має окреме повідомлення українською та англійською.

Ревізія профілів змінена на command-masks-color-v2. Старі вимірювання beta.29 та їхні залежні маршрути швидкості потребують нового калібрування; вони не отримують нову перевірку заднім числом. Невдала спроба зберігає попередній актуальний профіль лише в межах нової ревізії.

На сторінці «Пензель» з'явився окремий статус придатності ядра для широкого планування. Для Size >1 обидва розміри стабільного ядра мають бути ≥2 px, як уже вимагав planner. Виміряні 1×2 або 1×13 px тепер явно жовті та не обіцяють прискорення. Size 1 позначений базовим. Перевірка швидкості H/V залишається окремою.

Planner, таймінги звичайного вводу, Speed Probe v5, audit acceptance і repair не змінені. Фізичні зсуви крапок та залежність стабільного ядра від матеріалу полотна не виправлені цим захистом. Не виконувалося послаблення RGB tolerance, автоматичне повторне фарбування або зміщення масок до візуального центру.

Перевірки: 237 Core / 64 WPF сценарії, default runtime і точні опубліковані DLL. Повторне читання 21 записаного beta.29 знімка відхиляє білий слід; обидва повні Size 1 набори залишаються відхиленими. Старі невдалі швидкі маршрути та слабкі крапки також залишаються відхиленими. Windows CI та контракт версій пакета наведені в Build_Manifest.json. Це офлайн перевірки, не новий тест у Rust.
