# Pixora 1.0.14-beta.26

Size у Rust не дорівнює діаметру в пікселях. Попереднє вимірювання `[1,9,1]` означало фізичну Chebyshev-дальність 4 px, тоді як 7 px у planner включали запас безпеки. Beta.26 розділяє ці поняття.

- **Виміряний слід:** три окремі крапки на різних чистих ділянках для кожної пари «форма / Size». Об'єднання змінених пікселів утворює можливий фізичний слід; перетин пікселів, що відповідають зафіксованому непрозорому кольору, утворює стабільне ядро. Маски прив'язані до координати команди миші, без перенесення в центр плями. Зберігаються before/after, координати, повтори й JSON профілів. Обрізаний слід або зміни сцени скасовують калібрування. Нові профілі публікуються лише після всіх трьох повторів.
- **Більші Size:** 1/3/10/20 можна калібрувати разом; 40/60/100 — окремо. Тест спочатку перевіряє достатність місця для незалежних крапок. Максимальний адаптивний Size піднімається до 100; невиміряні розміри не вигадуються.
- **Сім форм:** кожну позицію можна вибрати й відкалібрувати. Назви інших п'яти форм показано за номером у рядку Rust, щоб не плутати їхні ефекти з підтвердженими суцільними круглим (3) та квадратним (4). Увімкнений вручну автовибір може використовувати актуальні профілі різних форм з ядром щонайменше 2 × 2 px для широких штрихів. Текстури без повторюваного ядра не прискорюють точну заливку.
- **Planner:** широкий штрих перевіряє весь можливий слід у своїй кольоровій області. Прибирання тонких команд дозволене тільки в прямокутнику, який реально покриває виміряне ядро; його асиметричний зсув враховується один раз. Залишки країв перегруповуються в довгі горизонтальні/вертикальні штрихи. Пропозиція приймається лише коли її оцінений час менший за початковий, включно з перемиканнями форми/Size. Тонкий початковий маршрут збережений і потребує реального аудиту на краях.
- **Дофарбування:** зі старими даними фізична дальність відокремлена від консервативного радіуса. З новими масками центр шукається за стабільним ядром, а безпека перевіряє весь можливий слід. Журнал окремо рахує фізично недосяжні цілі (`UnreachablePixels`) і цілі з лише можливим, але не стабільним покриттям (`PossibleOnlyPixels`). Другі не видаються за гарантовано виправлені. Цілі — тільки `Missing AND expected`; Unknown не є цілями, але можуть потрапити під штрих у тій самій області кольору. Реальні пікселі перевіряються повторно з початковим зафіксованим RGB reference. План не змінює критерій PASS.
- **Колір і ввід:** штрихи різних форм лишаються всередині групи одного кольору. Перемикання форми/Size не вимагає повторного HEX кожного штриха. Форми та IDs профілів не змішуються в пакетах. Пауза відновлює форму потрібного штриха. ETA враховує форму й Size, а швидкі докази зберігаються окремо для форм і не успадковуються іншою формою. Додавання/зміна її масок робить старі докази цієї форми неактуальними.
- **Speed Probe:** вибір до Size 100. Для великого сліду можуть не поміститися 62 незалежні ділянки на звичайному полотні; UI пояснює це й залишає звичайний ввід. Просторові/швидкі критерії, затримки кандидатів, запас швидкості й RGB tolerance не послаблені.
- **Інтерфейс:** збережені прогрес, ETA й актуальний статус відновлюються при перебудові/зміні мови, включно з паузою та завершенням. Новий план/START очищає попередні показники. Нові підписи й повідомлення доступні українською та англійською. Скасування порівняння палітр тепер передається в adaptive planner і schedule.

Стабільне ядро підтверджене трьома знімками в конкретному середовищі; це не математична гарантія поведінки Rust за будь-якого FPS. Числовий Size 100 не обіцяє 100 px. Межі кольорів, матеріал полотна, провали кадрів і текстури потребують живої перевірки. Профілі прив'язані до координат Canvas, режиму, захопленого керування, позиції/розміру вікна й DPI. Старі файли лишаються сумісними; після переходу на маски застарілі маски не підміняються старими радіусами. Новий planner revision скидає сумісність старих RESUME.

Очікувана перевірка: 211 Core / 56 WPF сценаріїв, стандартний runtime і точні опубліковані DLL; конкретний результат містить Build_Manifest.json. Новий живий тест beta.26 не проведено. Перед тестом очисти Canvas, калібруй вибрану форму та потрібні Size. Rust convars/binds лишаються окремим експериментальним напрямом, без неперевіреного автоматичного виконання команд.
