# Pixora RC5: живий тест

Збірка: 1.0.14-rc.5+local-rc5-drawing. Розпакувати в нову папку; не змішувати DLL зі старою версією. Новий START: попередній checkpoint не відповідає зміненому маршруту.

1. На чистому полотні вручну встановити Interval 0.01 / Opacity 1.00. Завантажити Four Blocks або Test_02_Edges. Вибрати Standard / палітру або HEX і натиснути **«Підготувати до малювання»**. Очікується одна послідовність шести етапів: області, кольори, керування Size, сім розмірів, простір і швидкість робочого Size. Додатково перевіряється рух придатних великих пензлів. Доступні лише **2/3/5/7/10/15/20**. Невдалий додатковий етап не блокує Standard; він залишається невдалим/очікуваним у списку, а не стає зеленим вимірюванням.
2. Очистити крапки й лінії калібрування. Намалювати Standard / Rapid. Перевірити чорний квадрат, відсутність видалення непрозорого фону, відповідність прев’ю та країв. Галочки «Прибрати фон» немає. Прозорість із PNG зберігається окремо.
3. На тому самому полотні, з тим самим джерелом, detail, кольорами й графічними параметрами Rust повторити Standard / **Turbo**. Починати з чистого полотна. Порівняти краї, тонкі лінії, просвіти між проходами, колір та активний час. За потреби окремо Max Speed. Вони змінюють щільність руху/проходів, тому швидкість приймається лише разом із якістю. Не змінювати кілька параметрів одночасно.
4. Adaptive: після нової підготовки переглянути кожний великий Size. «Крапки підтверджені» недостатньо: потрібне **«Рух H/V підтверджено»**. Непідтверджений великий Size не повинен бути в запланованих командах. Виконання — Stable/Rapid, >=20 ms, окремі штрихи. Якщо обраний лише Size 3, UI має показати базовий fallback; це не доказ широкого прискорення.
5. Намалювати Four Blocks у Adaptive. Порівняти зі Standard / Rapid: зайві лінії, зміна відтінку після повторного проходу, краї, фактичні Size й пропуски моделі. Зберегти журнали й знімки H/V до/після/повтор, включно з відмовами. Непідтверджені прогалини не перетворюються на Covered. Нормальна видима крапка без спільного ядра не вважається PASS.
6. Пауза F6, згортання Rust, вихід із редактора й повернення на **те саме** полотно; ESC та продовження. Коли чат/накладка перекриває рамку, прибрати перекриття перед відновленням. Зміна DPI/геометрії потребує захоплення заново.

Записати точну мітку збірки, режим, профіль швидкості, detail, полотно/DPI, параметри графіки Rust. Передати session-csharp.jsonl, failures.jsonl, config-v3.json, last-run і brush-calibration (особливо motion-*), або ZIP експорту діагностики. Відео допомагає відновити послідовність; RGB/mask перевіряти за lossless PNG, а не AV1 кадрами.

Додаткові швидкісні протоколи для інших Size доступні у груповій перевірці. Одна основна підготовка перевіряє швидкість **вибраного робочого Size**, не сертифікує прискорення всіх розмірів чи форм. Якщо для всіх проб бракує чистого місця, калібрувати меншу групу окремо; Standard зберігає доступність після його обов’язкових етапів.
