# Живий тест beta.59

Мета: перевірити відтворені збої beta.58, окремо від офлайн-перевірок.
Перед тестом збережи поточні config/session та працюй на чистому тестовому полотні.
Старий checkpoint не сумісний із новим протоколом звичайного руху: потрібен START.

1. **Підготовка:** палітра 4 або 16 кольорів, Hard Round, working Size 3.
   Запусти одну підготовку. Перевір, що Interval 0.01 не відхиляється після
   перевірки Opacity; курсор не закриває Size/Interval/Opacity або ряд іконок.
2. **Малі розміри:** combined calibration Size 2/3/5/10 на чистому полотні.
   Під час proof для Size 2 дозволене тимчасове перемикання на Size 3, але
   сама крапка має бути Size 2. Відмова не повинна блокувати наступну перевірку Size 3.
   Профіль приймається тільки за чинними критеріями; FAIL залишається FAIL.
3. **Ручне виправлення:** після невдалого speed/spatial етапу виконай його окремо.
   За нового PASS мають узгодитися чіп, рядок підготовки та readiness text.
4. **STOP/RESUME:** чотири кольорові блоки; зупини після першої групи.
   RESUME має стати доступним після завершення worker без зміни image/settings.
   Повторний STOP під час зупинки не має скидати його. Після зміни зображення
   або painting settings старий checkpoint має відхилятися.
5. **Baseline:** заверши один тест; очисти Canvas; почни той самий image
   і зупини під час countdown. Продовження не повинно читати baseline попереднього
   полотна. Без початкового кадру результат аудиту має бути Unknown/unavailable.
6. **Краї:** ordinary Size 3, чисті блоки та тонкі горизонтальні/вертикальні лінії.
   Перевір start/end і зворотний рух. Збережи final-summary, before/after/gaps/unknown.
   Запиши окремо Target/Confirmed/Missing/Unknown і UnplannedPixels; 100% команд не є PASS.
7. **Adaptive:** повтори той самий target, палітру, settings і timing на чистому Canvas.
   Порівняй час, counts за Size, командні operations, modeled coverage і final audit.
   Виграш у часі за гіршого coverage не є успішним прискоренням.
8. **ETA та UI:** запиши оцінку до старту та на 10/25/50/75%; рання оцінка
   повинна позначати уточнення темпу. Після зміни image старий audit має бути
   явно попереднім, а поточний progress/coverage — скинутим.

Для аналізу потрібні `session-csharp.jsonl`, `config-csharp.json` і знімки
діагностики; відео корисне для початку/кінця штрихів та руху між контролами.
Нова beta.59 у Rust ще не перевірена. Цей документ — checklist, а не звіт про PASS.
