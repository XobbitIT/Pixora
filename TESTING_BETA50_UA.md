# Pixora 1.0.14-beta.50 — список живого тесту

Розпакуй весь архів в нову папку, закрий попередню Pixora і запусти нову. Збережені налаштування можуть лишитися; повне видалення конфігурації не потрібне. Перевір beta.50 у заголовку. **Очисти полотно: старий RESUME несумісний з новим планером.**

1. **Палітра без HEX.** На «Малювання» натисни «Палітра Rust». У Rust також відкрий звичайну палітру. Натисни «Налаштувати та перевірити все» або виконай окреме захоплення палітри й керування. Відкрий `Testing/Images/Four_Blocks.png`, вибери робочий Size 3 і почни малювання. Очікується вибір клітинок палітри без введення HEX. Відтінки можуть відрізнятися від оригіналу через обмежену палітру Rust.
2. **Оновлення статусів.** На «Пензель» зміни значення прозорості на 0.75 у додаткових полях і перевір реакцію готовності без переходу на іншу сторінку. Поверни 1. Перевір оновлення статусів «Підготовка» після зміни робочого Size і Size тесту швидкості.
3. **Комбіноване малювання без Size 1.** Виміряй 3/10/20, залиш Size 1 невиміряним. Увімкни «Адаптивний пензель». Він має ввімкнутися, якщо є хоча б одне актуальне стабільне ядро. Постав максимум 20. При наявності великих суцільних областей мають використовуватися широкі Size, для менших ділянок — 3. Різні форми використовуються лише після їх власних вимірювань і ввімкнення автоматичного вибору форм.
4. **Межі кольорів.** Перед START переглянь попередження про ділянки без команд і їх рожеву маску. Намалюй Four Blocks на чистому полотні. Колір не повинен переходити у сусідню кольорову область за моделлю виміряного сліду. Порівняй фактичні краї зі знімком плану; залишені тонкі області не слід трактувати як успішне 100% покриття.
5. **HEX.** Очисти полотно. Перемкни Pixora на «Прямий HEX», відкрий HEX у Rust та перевір його власне захоплення. Повтори Four Blocks. Кожний колір має завершуватися перед наступним; фінальний відтінок і межі перевір окремо.
6. **Speed Probe для Size 3.** Вибери 3 на «Тест швидкості». Виконай просторове калібрування, очисти полотно, потім тест швидкості. Якщо кнопка вимкнена, наведи курсор: причина має бути видима. Зміни Size тесту на 10 — підтвердження 3 не повинне робити 10 «перевіреним». Поверни 3. Зміна захоплення або його маски має робити старий доказ застарілим з поясненням.
7. **Size 1 необов'язковий.** За бажанням виміряй лише 1. Якщо він відхилений, Size 3/10/20 повинні лишитися доступними, чіп робочого Size 3 — актуальним. Вибраний непідтверджений робочий Size 1 має блокувати START з поясненням. Якщо вимірювання 1 успішне, він може брати участь у комбінованому плані деталей.
8. **Ремонт і продовження.** На «Тест швидкості» ввімкни «Перевіряти після кожного кольору», прозорість 1; за бажанням — ремонт. При наявності пропусків він має використовувати підтверджений придатний пензель. Перевір форму і Size наступного кольору після ремонту. Окремо перевір F6/продовження та ESC на новому запуску beta.50.
9. **Велике зображення й ETA.** Лише після коротких тестів порівняй одну картинку з 64 та 128 HEX-кольорами, однаковим захопленням, деталізацією і вимірюваннями. Запиши операції, пікселі без команд, активний час, ETA на 25/50/75%, якість країв. Не роби висновок про швидкість лише за меншим числом команд: нова модель також може залишити непоміщені ділянки.

Для аналізу збережи `session-csharp.jsonl`, актуальний `config-csharp.json` і відео короткого тесту. Діагностика аудиту і Probe доступна з їх сторінок. Не повторюй двогодинний запуск до перевірки коротких тестів 1–6.

Ця збірка перевірена офлайн: 388 Core / 125 WPF. Нового живого тесту Rust розробником немає.
