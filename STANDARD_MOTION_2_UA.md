# Standard Motion 2 — зміни виконання штрихів

18.10.2026 · `1.0.14-rc.8+local-standard-motion-2`.
База: Standard Direction 1. Код малювання змінено; живий ввід у Rust у цьому етапі не запускався.

## Що змінено

### 1. Щільний маршрут у самому емітері Standard

Планувальник уже створював щільні смуги, але `StandardStrokeMotion` використовував `speed.Pitch` і для руху вздовж них. Turbo надсилав точки через 2 px, Max Speed — через 3 px. Розрахунок усіх центрів у плані не означав, що всі вони потрапляли в події вводу.

Новий емітер `standard-sendinput-dense-v2` надсилає кожну цілу координату від початку до кінця ортогонального відрізка, в обох напрямках. Проміжні точки додані всередині тих самих просторових пакетів: максимум 16 точок для Turbo та 48 для Max Speed. Safe і Rapid вже мали крок 1 px.

Кінці пакетів, число викликів Move, запитані Wait, плановані штрихи, порядок кольорів, target і щільність сусідніх проходів збережено. Вигаданого масштабу або зміщення координат немає. Немає додаткового проходу поверх малюнка.

**Межа висновку:** пропуски подій вводу відтворено й усунуто. Це не доказ пропуску тієї самої кількості пофарбованих пікселів у Rust: гра могла інтерполювати рух. Пакетні події також не доводять, що Rust прочитав кожну з них. Нерівність, раніше зафіксована в Rapid, цим механізмом не пояснюється.

### 2. Контроль фактичних кінців штриха

Звичайний Standard тепер викликає наявний guard фактичної позиції перед mouse-down і після mouse-up. Перевірка початку не дозволяє починати штрих із непідтвердженої позиції. Помилка читання/невідповідність зупиняє ввід із чинною причиною помилки курсора. Завершальну перевірку виконано після відпускання, щоб її можливий capture або журналювання не утримували фарбу на кінці.

Усі рухи залишаються в `GuardedNativeInput`; перевірки фокуса, редактора, геометрії, інструмента та заборонених ділянок не послаблено. У разі винятку mouse-up виконується у finally.

### 3. Менше роботи під час захоплення кадру

У `Native.Screenshot` замінено поканальний цикл BGRA→RGBA на еквівалентну векторну обробку. Альфа, кольори, розміри й орієнтація кадру залишаються байт-ідентичними. Перевірка редактора, її частота та пороги не змінені.

На локальному буфері 2560×1440, 31 замір після прогріву, медіана лише цього перетворення: **2,0188 → 0,9259 мс**. Це скорочення приблизно на 1,09 мс; не прискорення всього capture у два рази і не вимір швидкості Rust. Решта синхронної роботи перевірки редактора залишається.

### 4. Сумісність

Нова ревізія емітера входить до PlanIdentity і ключа історії transport timing. Старі оцінки вартості розрідженого маршруту не використовуються для нового. Старий checkpoint не переписується до першого штриха нового START, але продовжувати старе частково намальоване полотно слід старою збіркою.

Функція `DrawLegacy` зберігає стару послідовність для Experimental fallback і вже зареєстрованих внутрішніх протоколів v1/v2. Їхній runtime context явно записує `standard-sendinput-v1`. Ці протоколи не є тестом нового dense-маршруту; повторювати їх користувачу зараз не пропонується. Native Shift prototype лишається окремим opt-in.

## Перевірка на збережених планах

Однаковим C# harness виконано дві DLL: доставлену Direction 1 та нову Motion 2. SHA фактично завантаженої DLL перевірено в кожному результаті. Для кандидатного harness використано окремий build-каталог, щоб кеш посилань MSBuild не підставив DLL з попереднього запуску.

| План | Операцій | Пропущених цілих координат у старих Move | У нових Move |
|---|---:|---:|---:|
| HEX, cell2, Rapid | 1462 | 0 | 0 |
| Той самий HEX, Max Speed | 1462 | 199018 | 0 |
| Попередня палітра, cell8, Max Speed | 1038 | 167954 | 0 |
| Попередня палітра, cell2, Rapid | 1111 | 0 | 0 |
| Завершений R2 18.10, cell8, Max Speed | 1171 | 202046 | 0 |
| Повний план незавершеного R4 18.10, Rapid | 37242 | 0 | 0 |

Це лічильник проміжних **командних** координат, не оцінка кількості дірок у фізичній фарбі. Для R4 відтворено весь план офлайн, а не оголошено завершення живого запуску.

У всіх шести випадках збіглися target RGBA, TargetIdentity, множини центрів з multiplicity для кожного кольору, кінці пакетів, кількість Move, повні хеші Wait і кількість операцій. Немає команд поза віссю або межами відрізка. PlanIdentity Standard навмисно новий. Заморожений старий emitter replay через `DrawLegacy` збігається з базовою DLL.

Номінальні паузи не зросли. **Фактичний час може змінитися:** у Turbo/Max більше подій усередині пакета, а перевірки кінців додають виклики API. Прискорення або рівність wall time не заявляються до спостереження в грі.

## Що залишається відкритим

Фізичне усунення хвилястості Standard **ще не підтверджено**. Збережені спостереження Rapid, позиційний тренд, вплив проєкції/текстури Rust та накладання сусідніх проходів не оголошено виправленими. Пороги RGB12/contrast80 і модель Adaptive не змінені. Нова збірка містить конкретні зміни виконання, але не сертифікацію всіх причин фізичного дефекту.

Повторний набір 24/60 діагностичних проб і загальні Alt-Tab/F6 тести не потрібні для отримання цієї збірки. Старі записи й налаштування збережені. Нового живого PASS, commit або push у цьому етапі немає.
