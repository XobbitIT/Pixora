# Standard Evidence 3b — один живий збір для погодження

Це уточнений сценарій з двома правками Qoder. Агент його в Rust не запускав. Мета — порівняти покроковий ввід і поточні пакети Standard та побачити межі чорної смуги до і після білого. Великий малюнок повторювати не потрібно.

**Тривалість:** попередньо плануй **5–15 хвилин**, залиш до **20 хвилин**. Це бюджет, а не виміряний ETA: час залежить від знімків, перевірок кольору й запису файлів. На 20-й хвилині збір автоматично зупиниться зі статусом INCOMPLETE та збереже наявні дані. Запитані очікування самого руху — близько 41 с при стандартному cycle delay; 20 мс очікуються на початку/кінці штриха, не на кожній точці. Точна сума для заморожених налаштувань буде в `duration-budget.json`.

1. Розпакуй **Pixora_Standard_Evidence_3b_Windows_x64.zip** в окрему папку. Старий Evidence 3 для цього сценарію не використовуй.
2. Відкрий у Rust окреме порожнє полотно. Чинне захоплення повинно мати щонайменше **900×920 фізичних px**. Останнє 1044×1043 підходить за розміром. Якщо геометрія й підготовка не змінилися, повторне захоплення не потрібне.
3. Потрібні підготовлені кольори, круглий пензель Size 3 та точні чорний/білий у палітрі або підготовлений HEX. Вручну залиш у Rust **Interval 0.01 / Opacity 1.00**: програма їх не читає і не налаштовує. Попередні проби та малюнки потрібно прибрати до запуску.
4. **Повністю закрий звичайне вікно Pixora**, потім запусти `Collect_Standard_Evidence.cmd` з нової папки. Збирач — окремий запуск тієї самої програми: одночасно другий екземпляр не допускається. Налаштування копіюються в каталог серії; користувацькі config і checkpoint не перезаписуються. За **10 секунд** поверни Rust на передній план з відкритим редактором. Звичайний «Почати» не натискай.
5. Залиш мишу й клавіатуру без дій. Програма виконає **42 проби / 44 колірні фази / 216 штрихів** без Undo: 36 одиничних H/V прямого/зворотного напрямку 16/64/400 px; дві складені H/V-смуги з окремими кадрами чорного й білого; **ще дві горизонталі й дві вертикалі по 400 px з поточними пакетами Max Speed**. Вони розміщені на окремих чистих ділянках. F6, ESC, втрата фокуса або небезпечний інструмент зупиняють серію як INCOMPLETE; автоматичного продовження немає.
6. Після **DATA_COLLECTED** збережи повністю новий каталог `Standard_Evidence/<дата-час-id>/`: protocol/settings, duration-budget, series-status, events, baseline, усі sample-каталоги, знімки й gzip-траси. Передай його ZIP для офлайн-аналізу. DATA_COLLECTED означає повноту збору, а не підтвердження якості.
7. При **INCOMPLETE** збережи ту саму папку з частковими даними й повідомленням. Повторно той самий каталог не запускається. Спочатку аналізуємо записану відмову, без повторення великого малюнка.

Базові 38 проб використовують Rapid/Pitch1/Batch1. Додані чотири — незмінний preset Max Speed: у dense-емітері **48 послідовних фізичних точок у повному пакеті** (Pitch3 × Batch16), а не крок малювання 3 px. Після пакета є одне фактичне GetCursorPos; усі надіслані точки зберігаються як команди, проміжні положення курсора не вигадуються. Службові вимірювання додають витрати, тому це не кваліфікація продуктивності.

Старий емітер v1 з пропусками по 3 px цією серією не перевіряється. Проби на різних місцях не замінюють B0-оцінку шуму в одній координаті. Порівняння після збору має враховувати позицію, напрямок і фактичні таймінги; нульовий дефект у Batch1 сам по собі не пояснить старі хвилясті малюнки.
