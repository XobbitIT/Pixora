# Pixora 1.0.14-beta.34 — Explorer Clipboard

Живий запис 06.10.2026 о 21:09 показав дві однакові відмови до початку вимірювання: «Не вдалося зберегти формат буфера обміну». Square №4 та Size 1 були вибрані правильно. Перевірка метаданих поточного буфера виявила доступний список фізичних файлів CF_HDROP і недоступний через GetClipboardData формат FileContents.

- CF_HDROP зберігається перед рештою форматів. Недоступний альтернативний FileContents більше не блокує роботу, якщо список містить тільки доступні фізичні файли/папки. Їхні шляхи та решта доступних форматів відновлюються після транзакції.
- Віртуальні файли без доступного фізичного списку, невідомі недоступні формати та помилки доступу залишаються причинами відмови до запису в буфер. Потоковий FileContents не експортується і не відновлюється як потік: для підтриманого випадку зберігається звичайне копіювання фізичних файлів.
- У журналі з'являється clipboard_capture: збереження фізичного списку або точний номер/назва проблемного формату та код Windows. Вміст файлів і текст буфера не потрапляють у ці записи.
- Додано перевірки політики, native regression для недоступного FileContents зі справжнім файлом та захисту virtual-only вмісту. Режим PIXORA_CLIPBOARD_CAPTURE_ONLY=1 дозволяє перевірити backup поточного буфера без його зміни та без керування грою.

Модель контрасту пензля, RGB tolerance, planner і швидкісні пороги не змінені. Цей hotfix відкриває можливість виміряти Square Size 1; успішне калібрування в Rust потрібно підтвердити живим тестом.
