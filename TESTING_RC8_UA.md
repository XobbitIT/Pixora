# Pixora RC8 — вузький живий тест

Мітка `1.0.14-rc.8+local-rc8-flow`. Спочатку два короткі Standard-прогони. Adaptive й сім Size зараз повторювати не потрібно. Фізична кривизна ще не оголошена виправленою.

1. Розпакуй весь ZIP окремо й перевір мітку у вікні. Старі логи/налаштування збережи. У Rust встанови Interval 0.01, Opacity 1.00, brush і чисте полотно.
2. Standard / палітра, те саме Test_02_Edges. У «Якість і швидкість → Оптимізація плану» видно стан об'єднання країв. Зафіксуй ON/OFF: для порівняння RC7/RC8 потрібні однакові опції. Size3, клітина цілі 2 px; геометрія незмінна між парними малюнками.
3. Відкрий інше за розміром чисте полотно всередині Rust. Натисни тільки «Підготувати до малювання». Очікування: новий Canvas запитується в цьому ж потоці; після Enter програма переходить до Colors/Size без ручних налаштувань. Неоднозначні межі мають дати відмову, а не Ready.
4. Один раз перевір F6/втрату фокуса під час підготовки: Paused і «Продовжити», без зеленого Ready. Скасування показує Cancelled. Потім заверши підготовку.
5. На чистому Canvas намалюй Test02 до кінця. Знімки до/після зберігаються автоматично. Завершені команди не є physical-quality PASS. PNG потрібні для геометрії; відео — для хронології.
6. Повтори Standard у HEX на тому самому layout, на чистому Canvas і з правильно захопленою HEX-панеллю. Достатньо одного завершеного короткого прогону; всі попередні інструменти й Size повторювати не потрібно.

Передай ZIP каталогу даних Pixora з `config-v3.json`, `session-csharp.jsonl`, `failures.jsonl`, `last-run`, `canvas-captures`, `editor-diagnostics`. Нативні PNG і `command-plan.json.gz` — у новому `last-run/<run>/`. Для скасованого прогону відсутній `native-after.png` очікуваний; збережи причину й час зупинки.

Пілот довгого/короткого Size3 і B0 призначаються після перевірки цього потоку. Не вмикай `diagnostic_debug` для оцінки швидкості: він додає витрати й не є B0-сертифікацією.
