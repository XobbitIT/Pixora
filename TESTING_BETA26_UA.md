# Живий тест Pixora beta.26

Запиши версію в шапці, роздільність, масштаб Windows, FPS і розміри Canvas. Закрий стару Pixora, повністю розпакуй новий архів в окрему папку. Не змінюй розмір/позицію вікна Rust між калібруванням та тестом. Не пересувай мишу під час автоматичного вводу. ESC зупиняє; для нового запуску потрібне чисте полотно.

1. **Вибір і переклад.** У «Пензель» перевір сім кнопок форм, вибір Size калібрування та максимальний Size 100. Перемкни Українська ↔ English. Перевір, що всі нові підписи/помилки читабельні. На початок вибери суцільний круглий (3), автовибір форм вимкни.
2. **Базові маски.** На чистому полотні вибери калібрування `1/3/10/20`. Має з'явитися 12 окремих крапок; по 3 повтори кожного Size. У «Виміряні розміри» має бути можливий слід, ядро й 3/3. Не порівнюй Size з кількістю px як однакові величини. Очисти полотно. У `%LOCALAPPDATA%/Pixora/brush-calibration/run-*` перевір before/after і profiles.json. За помилки не мають з'являтися нові успішні профілі; збережи журнал.
3. **Великі пензлі.** По одному відкалібруй 40, 60 та 100, щоразу на чистому полотні. По 3 незалежні крапки; попередні профілі 1/3/10/20 збережені. На надто малому полотні програма має повідомити про нестачу місця до вводу. Перевір відсутність обрізаних крапок. Не ввімкни великий Size без актуального вимірювання.
4. **Інша форма.** Вибери квадратний (4), повтори базове калібрування й один великий Size. Профілі круглого лишаються у списку. Повернення на іншу актуальну форму використовує її маски; зміна DPI/Canvas/позиції вікна робить їх неактуальними. Текстурні форми 1/2/5/6/7 калібруй по одній: ядро може бути порожнє — це нормальний результат, не привід показувати PASS чи використовувати її для широкого точного заповнення.
5. **Four Blocks без автовибору.** Чиста ділянка, Palette, Precision 1 px, Adaptive ON, max Size 20; спочатку audit OFF для порівняння операцій, потім окремий чистий запуск audit ON + repair ON. Повтори з max 40/60/100, якщо вони виміряні. Занотуй кількість команд, широких штрихів, час, вигляд меж. Велика форма не повинна заходити на інший колір або прозорий фон.
6. **Краї й аудит.** Дивись верхній край червоного блока, де раніше лишалося 966 пропусків у трьох рядах. У `coverage_repair_plan` перевір `TargetPixels`, `UnreachablePixels`, `PossibleOnlyPixels`, safety/physical reach або IDs масок. `Unreachable=0` саме по собі не є PASS. Після repair має бути новий `coverage_audit` зі справжніми Missing/Unknown. PASS — тільки коли Missing=0 і Unknown=0. Unknown не використовуються як цілі дофарбування. Відкрий overlay через чіп «Покриття», навіть після закриття банера.
7. **Автовибір форм.** Коли круглий і квадратний актуальні, увімкни його; перевір на великих однорідних областях. `adaptive_shape` має показати конкретні форми/профілі, якщо їх вигідно використовувати. Журнал `color_group` — одна група на колір; HEX не повинен вводитися заново через кожен широкий штрих. Якщо виграшу немає, відсутність перемикання правильна. Порівняй до/після з однаковими Size/FPS/картинкою.
8. **Speed Probe.** Для вибраної форми й Size 1/3 зроби просторове калібрування, очисти Canvas, потім швидкі проби. Шість controls і незалежні повільні контроли мають повністю пройти; 27/28 не дорівнює успіху. Інша форма не успадковує швидкість. Для Size 40/60/100 на звичайному Canvas може не вистачити місця; перевір пояснення й звичайний fallback. Не зменшуй затримку лише заради цифри без підтвердження покриття.
9. **Пауза/STOP/RESUME.** На новій картинці F6, вручну змінити Size/форму, F6: Pixora має відновити саме потрібну форму/Size й колір. ESC під час широкого штриха та дофарбування має відпустити мишу. RESUME лише для того самого нового плану без аудиту; після зміни масок/старого beta checkpoint має бути пояснення несумісності.
10. **Прогрес і мова.** Під час паузи або після завершення перемкни мову. Відсоток, done/total, ETA/час і статус мають зберігатися й перекладатися. Нове зображення/план/START має очистити старий результат.
11. **HEX 64/96/128/256.** Та сама картинка й геометрія; порівняй planner operations/wide/час/вигляд. Найцікавіше, чи менша палітра дозволяє більше виміряних широких штрихів. Реальний час вимірюй окремими чистими запусками. Скасування порівняння на великому Canvas не має показувати частковий результат чи вводити команди у гру.

Для аналізу передай відео, `%LOCALAPPDATA%/Pixora/session-csharp.jsonl`, config-csharp.json, потрібний brush-calibration/run-*, speed-probe/run-* і coverage-audit. Познач найкращий/проблемний запуск та час на відео. Цей список не означає, що новий beta.26 уже протестовано в Rust.
