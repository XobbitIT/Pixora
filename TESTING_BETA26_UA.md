# Живий тест Pixora beta.26

Запиши версію в шапці, роздільність, масштаб Windows, FPS і розміри Canvas. Закрий стару Pixora, повністю розпакуй новий архів в окрему папку. Не змінюй розмір/позицію вікна Rust між калібруванням та тестом. Не пересувай мишу під час автоматичного вводу. ESC зупиняє; для нового запуску потрібне чисте полотно.

**Початковий етап:** круглий (3), max 20, Auto Shape OFF. Спочатку кроки 1–5 з аудитом. До великих Size, квадратного й Auto Shape переходь лише після перевірки попереднього етапу. Статичні 3/3 штампи не підтверджують суцільний слід під час руху.

1. **Вибір і переклад.** У «Пензель» перевір сім кнопок форм, вибір Size калібрування та максимальний Size 100. Перемкни Українська ↔ English. Перевір, що всі нові підписи/помилки читабельні. На початок вибери суцільний круглий (3), автовибір форм вимкни.

2. **Базові маски.** На чистому полотні вибери калібрування `1/3/10/20`. Має з'явитися 12 окремих крапок; по 3 повтори кожного Size. У «Виміряні розміри» має бути можливий слід, ядро й 3/3. Не порівнюй Size з кількістю px як однакові величини. Очисти полотно. У `%LOCALAPPDATA%/Pixora/brush-calibration/run-*` перевір before/after і profiles.json. За помилки не мають з'являтися нові успішні профілі; збережи журнал.

3. **Speed Probe.** Для вибраної форми й тих Size/напрямків, які реально використовуватимуться, зроби просторове калібрування, очисти Canvas, потім швидкі проби. Шість controls і незалежні повільні контроли мають повністю пройти; 27/28 не дорівнює успіху. Інша форма не успадковує швидкість. Для Size 40/60/100 на звичайному Canvas може не вистачити місця; перевір пояснення й звичайний fallback. Не зменшуй затримку лише заради цифри без підтвердження покриття. Доказ Size 1/3 не підтверджує Size 10/20. Якщо доказ для пари Shape/Size відсутній або calibrated strokes вимкнено, познач звичайний маршрут як неперевірений: потрібен окремий audited запуск із тими самими параметрами вводу. Збережи налаштування режиму вводу, затримки, fast_transfer і calibrated_strokes.

4. **Four Blocks без автовибору.** Чиста ділянка, Palette, Precision 1 px, Adaptive ON, max Size 20; audit ON + repair ON, один repair pass. Збережи окремо результат першого аудиту й повторного аудиту після repair; не оцінюй якість лише за завершеним дофарбуванням. До великих Size переходь у кроці 8 після прийнятного результату max 20. Занотуй кількість команд, широких штрихів, час, вигляд меж. Велика форма не повинна заходити на інший колір або прозорий фон.

5. **Краї й аудит.** Дивись верхній край червоного блока, де раніше лишалося 966 пропусків у трьох рядах. У `coverage_repair_plan` перевір `TargetPixels`, `UnreachablePixels`, `PossibleOnlyPixels`, safety/physical reach або IDs масок. `Unreachable=0` саме по собі не є PASS. Після repair має бути новий `coverage_audit` зі справжніми Missing/Unknown. PASS — тільки коли Missing=0 і Unknown=0. Unknown не використовуються як цілі дофарбування. Відкрий overlay через чіп «Покриття», навіть після закриття банера.

6. **Пауза/STOP/RESUME.** На новій картинці F6, вручну змінити Size/форму, F6: Pixora має відновити саме потрібну форму/Size й колір. ESC під час широкого штриха та дофарбування має відпустити мишу. RESUME лише для того самого нового плану без аудиту; після зміни масок/старого beta checkpoint має бути пояснення несумісності.

7. **Прогрес і мова.** Під час паузи або після завершення перемкни мову. Відсоток, done/total, ETA/час і статус мають зберігатися й перекладатися. Нове зображення/план/START має очистити старий результат.

8. **Великі пензлі.** Лише після перевірки max 20 по черзі відкалібруй 40, потім 60, потім 100, щоразу на чистому полотні. По 3 незалежні крапки; попередні профілі 1/3/10/20 збережені. На надто малому полотні програма має повідомити про нестачу місця до вводу. Перевір відсутність обрізаних крапок. Не ввімкни великий Size без актуального вимірювання. Після кожного нового Size проведи окремий Four Blocks з аудитом і одним repair pass на чистому полотні, зі збереженням результатів до/після. Якщо є нові прогалини, SceneChanged або вихід у сусідній колір, не збільшуй Size далі. Великий Size без Speed Probe не оголошується перевіреним за швидкістю.

9. **Інша форма.** Вибери квадратний (4), повтори базове калібрування, Speed Probe та audited Four Blocks max 20 перед великими Size. Профілі круглого лишаються у списку. Повернення на іншу актуальну форму використовує її маски; зміна DPI/Canvas/позиції вікна робить їх неактуальними. Текстурні форми 1/2/5/6/7 калібруй по одній: ядро може бути порожнє — це нормальний результат, не привід показувати PASS чи використовувати її для широкого точного заповнення. Текстурні форми лиши на кінець як окремий експеримент.

10. **Автовибір форм.** Коли круглий і квадратний актуальні, увімкни його; перевір на великих однорідних областях. `adaptive_shape` має показати конкретні форми/профілі, якщо їх вигідно використовувати. Журнал `color_group` — одна група на колір; HEX не повинен вводитися заново через кожен широкий штрих. Якщо виграшу немає, відсутність перемикання правильна. Порівняй до/після з однаковими Size/FPS/картинкою. Цей етап — після успішного audited тесту круглого й квадратного окремо. Збережи Missing/Unknown до та після repair і порівняй саме перший прохід за однакових параметрів. Відсутній доказ руху будь-якої використаної пари Shape/Size має лишатися видимим у записі тесту.

11. **HEX 64/96/128/256.** Та сама картинка й геометрія; порівняй planner operations/wide/час/вигляд. Найцікавіше, чи менша палітра дозволяє більше виміряних широких штрихів. Реальний час вимірюй окремими чистими запусками. Скасування порівняння на великому Canvas не має показувати частковий результат чи вводити команди у гру.

Для аналізу передай відео, `%LOCALAPPDATA%/Pixora/session-csharp.jsonl`, config-csharp.json, потрібний brush-calibration/run-*, speed-probe/run-* і coverage-audit. Познач найкращий/проблемний запуск та час на відео. Цей список не означає, що новий beta.26 уже протестовано в Rust.
