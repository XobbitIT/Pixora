# Standard: самостійна діагностика та прототип штатної лінії

Історичний стан першого прототипу v1. Відповідь Qoder для v2 — `NATIVE_LINE_QODER_RESPONSE_UA.md`; поточна діагностика v3 — `STANDARD_LINE_LAB_UA.md`. Прототип лишається вимкненим за замовчуванням.

Дата: 17.10.2026. Остання передана користувачу збірка — `local-standard-quality-1`. Робочий код цього етапу — `local-standard-line-prototype`; новий емітер **вимкнено за замовчуванням**, він не оголошений фізично перевіреним. Нових малювань від користувача не запитано. Adaptive не змінюється.

## Уточнена причина пошуку

Відтворення оригінальної DLL RC8 на записувальному fake дало 1020 операцій, 31521 точку при утримуваній кнопці та нуль виходів із запланованої осі/відрізка. Для трьох вертикалей це 27 довгих проходів по470px. Це перевірка чистого емітера, не реальної доставки Windows/Rust.

Із наявного відео виділено ранні кадри, що відповідають вузькому першому проходу (усі390 фіксованих внутрішніх рядків заповнені, ширина1–6px при діагностичному maxRGB<60). Ліві краї збігаються з фінальним нативним PNG у383/390,379/390,386/390 рядках; у всіх390 рядках різниця не перевищує1px. Дублікати кадрів не є незалежними повторами. AV1-кадр не є нативною квитанцією окремого paint-down; синхронізація за часом приблизна. Тому результат вказує на раннє походження нерівності, але не сертифікує її конкретну причину.

Додатковий діагностичний розрахунок положення країв за50% контрасту відносно попереднього чистого кадру дає максимальні залишки центрів≈0.85/0.65/0.59px. Попередній чистий кадр не є одночасним еталоном. Ці числа не замінюють RGB12/contrast80 і не є критерієм PASS.

## Обґрунтування нового шляху

[Facepunch описує штатний Line Tool](https://rust.facepunch.com/news/shipshape): Shift утримується під час перетягування для малювання прямої. Його наявність зазначена й в [офіційному changelist від05.03.2026](https://rust.facepunch.com/changelist/4032). Це первинне джерело про доступний механізм, а не доказ якості нашої послідовності на конкретному Rust користувача.

Попередній Standard завжди вимикав `line_mode` і застосовував пакетований вільний рух. У прототипі пряму між кінцями формує Rust; емпіричні offsets/scale та змінені колірні пороги не використовуються. Гіпотеза: це дозволить прибрати залежність геометрії довгого штриха від проміжного вільного руху. Гіпотеза ще не підтверджена живим запуском.

## Реалізовано

- `StandardLineMotion` із revision `standard-native-shift-line-v1`. Лише явний внутрішній `standard_native_line=true` у Standard; типово прапорець відсутній/false. Adaptive/калібрувальні маршрути та revision старого емітера збережені.
- Послідовність: початкова точка → кадр → Shift down → кадр → mouse down → кадр → кінцева точка → кадр → mouse up → кадр → Shift up → кадр. Час відпускання враховує більший configured Release. При перериванні натиснуті Shift/миша відпускаються в finally. Нульова довжина залишається звичайною крапкою.
- Перед першим вводом перевіряється весь відрізок, включно з проміжними пікселями та чужими вікнами; безпечні кінці не дозволяють перескочити через no-go. Збережені перевірки редактора, фокуса, інструмента, кольору, Canvas, DPI та API курсора. Координати не затискаються й не пересуваються.
- Ціль і геометрія coverage не змінені. У прототипу окремі PlanIdentity/контекст таймінгів; старі checkpoints та rate історія не використовуються для нового методу. Знайдено й виправлено залишковий дефект: непідтверджений `motion_transport_rate` зі snapshot тепер очищується перед завантаженням лише історії відповідного контексту.
- ETA рахує фактичну послідовність прототипу. У command evidence метод позначено `native-line-prototype`, physicalResultVerified=false. Немає заяви про прискорення.

## Причинний replay короткого файлу

Підготовлено72 операції для того самого target трьох вертикалей. Нова DLL із прапорцем OFF точно відтворює target, семантичну PlanIdentity, schedule та номінальний емітер переданої Quality1 DLL. З ON target і schedule залишаються тими самими, але послідовність вводу інша:11376→144 точок руху,792→144 викликів Move,0→144 змін Shift. Запитані очікування5.8104→8.64с, без API/guard/render витрат. Це не вимір продуктивності Rust.

## Межі готовності

Підсумок перевірок цього робочого коду:584 Core-тести та171 WPF-сценарій, включно з84-layout DPI matrix, PASS; обидві збірки0warnings/0errors. Нові4 Core-перевірки охоплюють opt-in/ідентичність цілі, H/V/reverse/короткі лінії, усі12 переривних фаз та no-go всередині шляху. Нові3 App-перевірки охоплюють чужі вікна/контроли всередині відрізка, контекст часу та точне маркування evidence. В офлайн-хості SendInput заборонено.

Офлайн-перевірки доводять порядок вводу, відпускання при помилках, незмінність target, ізоляцію контекстів і guard усередині відрізка. Вони не моделюють внутрішній рендерер Rust, форму/товщину лінії, частоту кадрів, накладання або реальний кінцевий вигляд.

Новий емітер не вмикається звичайним користувачам до перевірки фізичного результату. Попередні ZIP залишені незмінними, commit/push не виконувалися. На цьому етапі додаткових дій користувача не потрібно. Документ і delta evidence призначені для точного review реалізації, а не як заміна живого підтвердження.
