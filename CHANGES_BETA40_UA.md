# Pixora 1.0.14-beta.40 — підтвердження числових полів і HEX

- Запізніла відповідь на очікуваний Ctrl+C від процесу Rust більше не вважається сторонньою зміною буфера при наступному записі або відновленні. Зміни від стороннього або невідомого процесу перед записом і надалі зупиняють операцію та зберігаються.
- Після невдалого читання числового поля чи HEX програма повторно фокусується подвійним кліком і використовує повільніші клавіші лише в повторній спробі. Успішний перший прохід і затримки мазків не змінюються.
- HEX очікує завершення копіювання кількома короткими опитуваннями без повторного запису маркера між ними. Для успіху потрібен точний збіг кольору.
- У session-csharp.jsonl з’являються clipboard_sequence: операція, очікуваний і фактичний номер зміни, процес-власник, очікуваний процес Rust та наявність очікуваного копіювання. Ці події не містять тексту користувацького буфера.
- Помилка буфера більше не стверджує, що причиною обов’язково є стороннє копіювання. Текст доступний українською й англійською.
- При фатальній помилці виділення пам’яті WPF програма звільняє ввід і завершується замість повторного відкриття діалогів у несправному рендері. Це обробка наслідків, а не підтверджене усунення причини старого збою beta.31.

Підстава: ноутбук beta.39 — Size 7/7, Interval 0/7, два START із Done=0, нестабільний HEX readback. Живий результат на ноутбуці ще не перевірено; виправлення фокусу є обмеженим маршрутом повторної спроби, а не гарантією, що координати захоплення правильні.

Критерії підтвердження чисел, позиції повзунків, покриття, калібрування пензля і Speed Probe не послаблені. Проблеми фізичної моделі пензля зі звіту ПК залишаються окремою задачею.

Перевірено локально: 305 Core і 95 WPF перевірок пройшли; збірка — 0 помилок, 0 попереджень. Нові regression-сценарії охоплюють пізню відповідь Rust до запису/cleanup, сторонню й анонімну зміну, конфлікт між перевіркою й записом, відсутність витоку вмісту clipboard у діагностику, пропущені й неправильні HEX-відповіді, скасування та відновлення фокусу поля. Нативний clipboard і живий ввід у Rust у цих локальних тестах не запускались.
