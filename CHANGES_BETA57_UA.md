# Pixora 1.0.14-beta.57 — ціль, покриття та прогноз часу

База: beta.56, `5c347c2652f4eb6a90fe8baaad7327bc42d27673`. Локальна збірка, без нового живого прогону й без публікації в GitHub.

## Що змінилося

- **Об’єднання тонких ділянок** у квантованій цілі: до трьох проходів із замороженими рішеннями, прозорість зберігається. Типово ввімкнено, товщина 2 px у сітці зображення. Товщина визначається найбільшим вписаним квадратом; поріг площі враховує найменше актуальне підтверджене ядро та масштаб полотна. Опцію можна вимкнути. Є два прев’ю та кількість змінених пікселів/областей. Зміна цілі інвалідує план, але не калібрування фізичного пензля.
- **Фінальний аудит після завершення команд** виконується завжди. Окремо показані частки підтверджених, пропущених і невизначених пікселів. 100% команд не означає 100% покриття; непевні пікселі не стають цілями дофарбування. Діагностика містить знімки до/після, пропуски та окремий помаранчевий шар Unknown зі збільшенням. Додатковий аудит і дофарбування після кожного кольору залишаються опцією.
- **Локальні еталони аудиту** на плитках 128×128 зменшують неоднозначність при різному освітленні великих областей. Викликається той самий `CoverageAudit.Read`, з незмінними порогами й глобальною перевіркою зміни сцени поза ціллю.
- **ETA як діапазон:** до 20 успішних операцій — попередня верхня оцінка; далі 0,9–1,15 від поточного прогнозу. Корекція за останніми 50 циклами включає зміни Size/форми, малювання й службову роботу. Колір, захоплення, аудит і завершення враховуються окремими вимірюваними етапами. Пауза та невдалі повтори не є калібрувальними спостереженнями; накладні витрати не додаються двічі.
- **Порівняння звичайного й Adaptive:** час за моделлю, операції та піксельне покриття. Рекомендація надається лише дешевшому плану, який не втрачає жодного пікселя покриття іншого. Застосування — окрема дія користувача.
- **Доказ застосованого кольору палітри:** після кліку два знімки активного зразка мають відповідати очікуваному RGB у межах 12. Лог `palette_cell_proof` відокремлений від перевірки вихідної комірки. Непідтверджена група пропускається без малювання, включно з відновленням після паузи; наступні групи можуть продовжити. Непідтверджений колір під час repair не використовується. Відсутній активний зразок також не є доказом. Єдина підготовка запитує його захоплення, якщо потрібно.
- **Локалізація:** 946 міжнародних шаблонів; CI перевіряє всі 834 активні ключі інтерфейсу, статуси малювання та власні технічні помилки для п’яти додаткових мов. Вкладені причини помилок теж перекладаються. Старі однопараметричні переклади не змінено. Файлові шляхи, HEX і повідомлення ОС не перекладаються.
- **Перевірка UI:** 84 рендери WPF — 7 мов × 3 масштаби DPI × початковий/готовий/паузний/аудитний стан. Перевіряються справжні розміри та видимість START/STOP і ширина їхніх підписів; це офлайн-композитор, а не керування Windows чи Rust.

## Перевірки та межі доказів

Release: 0 warnings / 0 errors. Core: 459 перевірок; WPF: 168 перевірок, включно з 84 рендерами. Окремо повторюються тести з точними DLL фінального пакета.

Для восьми сценаріїв BVB/FCB/тризуба вимкнене об’єднання має ідентичні beta.56 мітки/identity, хеш маски покриття та кількість операцій. Новий фінальний аудит і підтвердження палітри додають власну вартість, тому весь час запуску не зобов’язаний збігатися зі старою версією.

Синтетична AA-фікстура виконує критерій ≥30% менше unplanned та менше операцій, зі збереженням товстих областей. На реальних вхідних зображеннях виграш швидкості **не універсальний**: більша кількість доступних для малювання пікселів іноді вимагає більше команд. Числа моделі й хеші — `Testing/Offline_Model_Replay.json`.

Контраст калібрування 80, RGB tolerance 12, перетин масок, критерії Speed Probe, `CoverageAudit.Read` і константи транспорту вводу не послаблено.

**Біле на ідентичному білому фоні залишається Unknown.** Два однакових знімки не доводять нанесення фарби. Критерій ТЗ про зменшення Unknown для такого випадку не заявляється виконаним; потрібен незалежний додатковий доказ. Локальні еталони допомагають при неоднорідності освітлення, але не створюють відсутнього сигналу.

**ETA ≤8% перевірено лише симуляцією на агрегованих швидкостях наданих beta.55 журналів.** У них немає індивідуального часу кожного циклу для точного відтворення нового алгоритму. Новий записаний beta.57 прогін потрібний для приймання живого ETA; старі журнали не називаються тестом нової версії.

Фінальний аудит перевіряє наявність покриття відносно локального еталона, а не незалежну абсолютну RGB-точність кожного пікселя. Активний зразок палітри підтверджує вибраний колір; не називається доказом RGB фарби на полотні. Для полотна понад 4 млн px або відсутнього стабільного знімка результат — непідтверджений із причиною. Відновлення використовує збережений початковий знімок того самого плану; без нього — Unknown.

Pixora.exe, Rust, SendInput і native clipboard smoke під час цієї перевірки не запускалися. `inGameTest=false`.
