# Standard: протокол дослідження невизначеності

22.10.2026. Ревізія `standard-uncertainty-study-v2-proportional`. **Протокол діагностики; не production-policy й не дозвіл на малювання.** Він не задає числового U, не заморожує запропоновані межі якості та не змінює runtime. [Контракт](PHYSICAL_QUALITY_CONTRACT.md).

## Що вже перевірено

У наявному frozen ascending-наборі 21.10 знайдено 26 пар свіжих захоплень одного записаного стану: `stroke-i-after` → `stroke-(i+1)-before`; для останнього проходу — `stroke-012-after` → stage `after`. Код колектора виконує друге захоплення до наступного Draw; у журналі між ними немає `stroke_started`, `stroke_emitted` або `colour_started`. Верифіковано file/RGBA hashes, незмінний rect, неперекриті QPC capture windows та повні 401 переріз кожної пари.

Результат: **10426/10426 перерізів, 20852 порівняння країв, max/P95 різниці 0 px** для `native-band-local50-radius32-v1` з незмінним baseline. Повністю однакових RGBA пар лише 4/26; у решті максимальна RGB-різниця всього Canvas — до 4. Проміжки між завершенням першого та початком другого захоплення — 0.3693662–0.6664785 s. [Аудит](../../../physical-metrics-closure-20261022/passive-pairs.json), [усі перерізи](../../../physical-metrics-closure-20261022/passive-pair-edges.csv).

Важливе уточнення: **усі 26 пошукових RGB-смуг 65×401 px байт-ідентичні** між парними кадрами; RGB-відмінності розташовані поза ними. Тому нульова різниця країв очікувана й не перевіряє чутливість extractor до локального шуму.

Це retrospective-діагностика однієї сесії, два захоплення кожного з 26 різних станів. **Не 26 незалежних повторів одного стану.** Вона не відділяє capture від рендерингу, не варіює чистий baseline, не оцінює абсолютний bias і не засвідчує production observable. `e=0` або `U=0` з неї не випливає. Нерівний, але незмінний слід може повторюватися ідеально.

## R — обмежена повторюваність незмінного стану

До нових кадрів в immutable manifest фіксуються: build/source/capture/extractor hashes, geometry/DPI/origin, повний Canvas rect, target, усі обов'язкові body/cap/edge ROI, baseline ID, поточна історія кольорів/проходів і raw reference. Нові умови не змішуються з набором 21.10; коли цей самий контекст відсутній, він оголошується новим.

Одна опційна серія — **4 свіжі native кадри одного вже намальованого стану**, у двох часових моментах: t=0,1 s і t=60,61 s за monotonic clock. Зберігаються фактичні QPC begin/end, UTC, номер/запланований час, raw RGBA/file SHA та context. Прострочений/відсутній кадр invalid/missing; його не замінюють зручним дублем. Це лише діагностика двох моментів, не доведена статистична незалежність і не універсальний e-bound.

Manifest окремо записує неконтрольовані умови: ігровий час/освітлення, погоду, рух/положення камери, стан HUD/оверлеїв та відомості, звідки це взято. Невідоме лишається UNKNOWN; збирач не вигадує стан погоди або контроль камери. Зміна/невідомість релевантних умов звужує scope або робить порівняння INCOMPLETE. У старій сесії ці фактори не записані, тому переносити її стабільність на інші сцени не можна.

Між кадрами немає малювання, Undo/Redo, зміни кольору, інструмента, Size, rect або освітлення за командою збирача; полотно не очищується, baseline не перезнімається. Курсор лишається у перевіреній тихій точці до першого reference. Автопаркування/налагодження, які потребують вводу, не є частиною пасивної серії. Невідомий foreground/tool/context, overlay на обов'язковому ROI або ручна зміна стану → серія INCOMPLETE, кадри зберігаються з причиною, paint не дозволяється.

До запуску фіксуються алгоритм, області та статистики: raw max RGB delta; для кожного краю/рядка — max абсолютної різниці до першого кадру й усіх попарних різниць; P95 nearest-rank по явно названому набору; counts missing/invalid; QPC duration/spacing. Немає registration/fitting, вибору найкращих кадрів, усереднення картинки перед виміром, виключення caps/junctions або заміни baseline. Відсутній обов'язковий край/кадр → INCOMPLETE, а не зменшений знаменник.

**Критерій R до збору:** обчислювати й публікувати тільки `REPEATABILITY_MEASURED`, якщо є всі 4 валідні кадри, незмінний context і всі зафіксовані краї. Інакше INCOMPLETE. Навіть нульовий розкид не дає `U_VALIDATED`, physical PASS або придатність профілю. Ненульовий розкид — спостережений факт, не автоматично верхня межа всіх майбутніх похибок. Статистичний/confidence bound потребуватиме окремої заздалегідь визначеної моделі залежностей і валідації; брати максимум із цих 4 як універсальне e заборонено.

## C — систематична похибка capture/координат

Потрібен окремий контроль із відомим походженням пікселів і фізичними координатами, представлений на тому самому моніторі без масштабування й захоплений тим самим `Native.Screenshot` (GDI BitBlt → GetDIBits → BGRA/RGBA), з відомими physical client origin/DPI/size. Перевіряються всі чотири межі, не лише центр. Зберігаються і source buffer, і captured buffer; PNG, двічі прочитаний із диска, не є повторним захопленням. Synthetic renderer перевіряє код/математику, але сам не доводить поведінку game rendering.

План областей/розташувань та точний байтовий/координатний oracle хешуються до capture. У цифровому контролі очікується **0 px координатного зміщення й точний RGB source pixels** у всіх обов'язкових контрольних точках. Відмінності не компенсуються fit-ом; невідомий compositor/color transform означає unavailable для цього точного oracle. Відсутність такого контролю лишає систематичну компоненту невідомою, навіть якщо R стабільний. Успіх C засвідчує capture-control, а не projection/paint Rust.

## E — observable й похибка виділення краю

До фізичного приймання окремо визначаються придатний observable, пари кольорів, шейдинг/фон, повнота Possible/Solid, caps/overlap і залежність від історії проходів. Local 50%-край лишається діагностичним. Його стабільність або мінімальна різниця двох довільних порогів не перетворює його на RGB12/Solid чи абсолютний фізичний контур.

Для перевірки bias потрібні independent reference та зафіксовані train/validation/untouched cases. Спочатку визначається, що саме є істинним краєм і яка uncertainty самого oracle. Synthetic antialiasing може перевірити інтерполяцію на відомій моделі; перенесення на Rust потребує окремого доказу. Невідомий oracle → extraction U unknown. Повторна baseline-компонента вимірюється окремо без повторного фарбування; її відсутність у нинішніх парах зазначена явно. Caps не сертифікуються з body CSV.

## Коли можливе U_VALIDATED

Потрібні обґрунтовані residual upper bounds саме в заявленому observable/context, включно з невизначеністю oracle та всіх необхідних baseline/after компонент. R, C і E — різні питання; їх не об'єднувати одним RMS. Якщо доведено uniform edge-bound e, застосовуються умовні фактори k=1/2/4 із контракту; компоненти metric U складаються **лінійно**, observed scatter вдруге не додається. Невідома частина → null/INCOMPLETE, ніякого автоматичного нуля.

Production budgets фіксуються до незалежного приймання: `metric+U_metric ≤ limit` для кожного обов'язкового випадку. Числові пропозиції 1.0/0.5 px лишаються чернеткою. Після огляду нових даних їх не підвищують для PASS; зміна методу/observable потребує нової ревізії та untouched validation. Без C/E поки немає підстав заморожувати e/U чи вносити коректор.

## Поточний наступний крок

Пасивний аудит наявних даних уже виконано; новий тест від користувача зараз не запитується. C виконано у вказаному вузькому scope. RGB12-mask перевірено як конкретну пропозицію й виявлено неповноту. Наступна фізична модель має зберігати повний слід/історію та обидві межі; невідомі descending, інші low-старти й caps не домислюються. За потреби нових фізичних даних береться наявний frozen frontier-протокол, без нового CLI; відсутнє не замінюється припущенням. Вводу в Rust, нового CLI/кнопки, змін START або Q/jitter цей протокол не додає. Він не є реалізацією фізичного вирівнювання.
