## Обсяг і ціль

Перший обсяг — Standard, круглий Size3, горизонтальні й вертикальні лінії та смуги. Обидва напрямки, одиночний штрих, послідовність паралельних проходів і межа двох кольорів — окремі випадки. Palette/HEX і кожен заявлений speed/emitter/context перевіряються окремо. Цей контракт не сертифікує Adaptive, всі форми чи інші Size.

Є два незалежні порівняння: **джерело → підготовлений target** та **target → фізичний результат**. Сходинки, вже присутні в target, належать першому порівнянню. Фізичні геометричні метрики нижче стосуються другого. Speed/route не можуть змінювати target задля кращого результату.

До оцінювання фіксуються target RGBA/mask і їхні хеші, фізичне відображення, бажані ширини/контури/caps, command rect, origin/DPI/client size, shape/Size, колір, emitter, порядок проходів, таймінги, build hashes, версія вимірювача й список обов'язкових випадків. Target identity окремий від execution/checkpoint identity. Ідеальний контур не відновлюється з намальованого результату або команд пензля заднім числом.

## Координати й спостережуване

Усі відстані — **фізичні екранні px**. Native capture має масштаб 1:1. Центри пікселів мають цілі screen-координати; область пікселя — `[x−0.5,x+0.5) × [y−0.5,y+0.5)`. Перехід screenshot→screen використовує тільки записаний origin. Жодної підгонки shift/scale/rotation за after-кадром під час приймання.

Для кожного заздалегідь визначеного перерізу `a` target задає `L*(a), H*(a)`; native-вимір дає `L(a), H(a)`. Для прямої H/V цільові поперечні краї сталі. Потрібні **обидва** краї, `L < H`, усі обов'язкові перерізи й незмінна відповідність координат. Немає можливості надійно виміряти край — `INCOMPLETE`, не нульова похибка і не пропущений знаменник.

Наявний `StandardBandResponse.MeasureSection` — діагностичний local-half-intensity вимір темної смуги: grayscale `(R+G+B)/3`, пошук ±32 px, одна компонента затемнення >80, background із зовнішніх 5+5 пікселів, половина background/найтемнішої внутрішньої точки, лінійна інтерполяція перетинів. Він залежить від спостережуваного тону. Це не заданий RGB, не Solid і не універсальний вимір білого/кольорової межі. Перед кваліфікацією окремо фіксуються придатний observable, його область застосування та похибка; невідповідну пару кольорів ним не сертифікувати. Старий Δ>80 цілочисельний midpoint і half-intensity edges не змішуються в одну серію.

## Незалежні метрики, погоджена ціль і запропоновані межі

Позначення: `eL=L−L*`, `eH=H−H*`, `w=H−L`, `w*=H*−L*`. Похибки не округлюються перед рішенням. P95 — nearest rank, індекс `ceil(0.95·M)−1` у впорядкованому масиві з `M` значень. Є **дві різні метрики**: `P95PooledAbsoluteEdgeErrorPx` по `2N` абсолютних похибках країв та `P95RowMaxAbsoluteEdgeErrorPx` по `N` значеннях `max(|eL|,|eH|)` кожного рядка. Старе ім'я `P95AbsoluteTwoEdgeErrorPx` збережено як read-only alias **pooled**, без зміни його значення. Pooled не означає «95% рядків у допуску».

| Властивість | Визначення | Межа та її статус |
| --- | --- | --- |
| Абсолютне положення | `max_a max(|eL|,|eH|)` | **погоджена ціль max ≤1.0 px**, рішення з per-metric U |
| P95 pooled | P95 по всіх `2N` абсолютних похибках країв | запропоновано ≤0.5 px; не погоджено разом із max |
| P95 найгіршого краю рядка | P95 по `N` значеннях `max(|eL|,|eH|)` | окрема діагностика; допуск ще не задано |
| Прямолінійність | `max(range(eL), range(eH))` на всій довжині | ≤1.0 px |
| Правильна ширина | `max_a |w−w*|` | ≤1.0 px |
| Сталість ширини прямої смуги | `max(w)−min(w)` | ≤1.0 px |
| Локальна сходинка | `max_a max(|eL(a+1)−eL(a)|, |eH(a+1)−eH(a)|)` по сусідніх фізичних рядках/стовпцях | ≤0.5 px |
| Обидва caps | Симетрична Hausdorff-відстань у L∞ між повними спостереженим і замороженим цільовим контурами кожного кінця; окремо signed longitudinal overshoot/undershoot | кожна відстань і абсолютний overshoot/undershoot ≤1.0 px |
| Стики й межа кольорів | Ті самі абсолютні краї/ширина/сходинки, до й після кожного зафіксованого накладання та на фіналі | ті самі межі; усі стики включено |
| Повнота | Відсутні перерізи, розриви потрібного покриття, непояснений чужий колір, вихід у заборонену область | 0; відсутні дані → INCOMPLETE |

Метрики положення та рівності не підміняють одна одну: рівна, але зсунута лінія провалює положення; правильний центр із мінливою товщиною провалює ширину. `MaxPerEdgeErrorRangePx` включає нахил; detrending не виконується. Залишок від власної OLS-прямої й її slope можна показувати як діагностику, але ними не замінюється порівняння з target. У смуги оцінюються обидва краї, не лише центр або рухомий high. Для caps нормативна відстань — **L∞ (Чебишевська)**, не евклідова: `HausdorffLowerBoundLInfinityPx` / `HausdorffUpperBoundLInfinityPx`. Старі назви без норми лишаються read-only aliases; числового переходу між нормами немає.

Область caps, body й стиків фіксується до прогону й разом покриває весь потрібний контур. Немає тихого вилучення перших/останніх рядків, «центральних 60%» або ±3 рядків біля jog. Окремий діагностичний crop дозволений лише з явним статусом, що він не покриває повний випадок. Пропозиції 0.1/0.3/1.0 для колишнього jog-прогнозу сюди не переносяться.

## Невизначеність і рішення

До заморожування контракту вимірюються повторюваність observable й незалежна систематична похибка capture/registration. Спостережений розкид уже входить у per-sample метрики; його не додавати вдруге. Для кожної метрики потрібна обґрунтована верхня межа залишкової невизначеності `U_metric`; зокрема для ширини, range, різниці сусідніх країв і caps вона може відрізнятися від похибки одного краю.

Для замороженої політики: `metric + U_metric ≤ limit` — PASS цього gate; `metric − U_metric > limit` — FAIL; перетин межі або відсутня/необґрунтована `U_metric` — INCOMPLETE. Невідомий шум не дорівнює нулю. Межа max-положення1.0 px погоджена користувачем; решта значень1.0/0.5 лишаються пропозиціями, не результатами B0. Їх не збільшувати після перегляду приймальних кадрів заради PASS.

Для ліній використовується **`CompareLineMetric`**, а не пряме передавання окремого поля в `CompareMetric`. Якщо `!line.Complete`, результат кожного порівняння — `Incomplete` / `line_incomplete` навіть при нульовій похибці доступних рядків або при явно великому частковому дефекті. Значення часткового виміру зберігається для діагностики; воно не є оцінкою повної лінії. Загальний `CompareMetric` лишається арифметичним helper без інформації про знаменник і повноту. Для фізичних рішень по лініях/caps його пряме використання заборонено.

Результати `StandardPhysicalLineMetrics` і `StandardPhysicalCapMetrics` — незмінні sealed classes з internal constructors та get-only полями. Публічні record-конструктори, `with` і десеріалізація довіреного результату вилучені; missing rows зберігаються окремою read-only копією. Зовнішній API створює результати лише через `MeasureLine`/`MeasureCap`. Це захист цілісності об’єкта від випадкової/звичайної зовнішньої мутації, не security boundary від ворожого коду в процесі. Фабрика приймає заявлені перерізи й provenance, а не перевіряє raw capture; збережені звіти перевимірюються з raw evidence. Context ID визначає scope U, не засвідчує значення метрик або виконання extractor.

До першого production-споживача встановлено контракт: **готовий `StandardPhysicalMetricComparison` ніколи не є входом-дозволом START чи іншого gate**. Він лишається public diagnostic record і може бути створений/змінений стороннім кодом. Споживач не довіряє `new`, `with`, JSON або збереженому WithinLimit: сам перевіряє raw evidence, актуальну frozen policy/context/U та виконує `MeasureLine` → `CompareLineMetric` разом з усіма незалежними gates. Сторонній comparison ігнорується; навіть коректний WithinLimit не є дозволом вводу. Перед першим production caller потрібні інтеграційні негативи на forged/stale comparison; зараз такого caller і відповідного приймання немає. Review0013 прийняв v3 як чисту геометрію; для цієї умови модуль не змінювався.

`StandardPhysicalLineProvenance` фіксує визначення краю, SHA256 алгоритму, геометрію захоплення, профільний context і SHA вихідного доказу. `ProfileContextSha256` має охоплювати колір/shape/Size, emitter/timing/mapping та **повну історію нанесення**, не лише назву пресета. `MeasurementContextId` обчислюється з ревізії метрик, target (вісь/напрямок/положення/довжина/ширина), визначення/хешу алгоритму, geometry/profile hashes; SHA окремого capture не входить у цей cohort-scope. Wrapper повторно обчислює ID із збережених target/provenance: зміна цих полів зі старим ID повертає `line_context_identity_mismatch`. Відсутні метадані або непідтримане визначення краю не допускають `WithinLimit`. Наразі wrapper підтримує лише діагностичний `native-band-local50-radius32-v1`. Валідний запис цього ID не є твердженням про RGB12, Solid чи production-придатність. Перед фізичним прийманням незалежно звіряються actual implementation hash, raw frames та scope; формат SHA сам по собі не доводить виконання алгоритму.

`StandardPhysicalLineUncertainty` вимагає відповідності metric/context, SHA незалежного дослідження й ревізії методу. Три компоненти — **залишкові верхні межі похибки саме обраної метрики**:

- `CaptureResidualPx`: обґрунтована похибка capture/реєстрації у незмінному фізичному context. Дані без вводу та незалежний геометричний орієнтир мають відділяти її від зміни фарби.
- `ExtractionResidualPx`: bias/похибка конкретного визначення й інтерполяції краю, встановлені на контрольній геометрії або незалежному еталоні. Це не розкид між різними префіксами й не різниця двох довільних порогів.
- `SamplingResidualPx`: доведена дискретизаційна/чисельна складова цієї метрики; нуль допустимий лише за явного обґрунтування, невідома компонента — `null`.

**Лінійна сума** `U_metric = CaptureResidualPx + ExtractionResidualPx + SamplingResidualPx`: консервативні residual upper bounds додаються арифметично, не квадратурно. `sqrt(sum(U_i²))` не дозволено без нового обґрунтованого контракту; незалежність компонент не припускається; невідома частина дає `Incomplete`, не автоматичний нуль. Для width/range/step/P95 дослідження має обґрунтувати перетворення похибок країв у похибку відповідної метрики; значення не переноситься між метриками. Повторюваність фарби між сесіями вже відображається в окремих фізичних вимірах; її не додавати як U вдруге. `IncludesObservedScatter=true` блокує порівняння. Згадані в review історичні 0.02–0.16 px не прийнято за U без перевірки observable/context. **Фізично валідованих числових U для цих ліній поки немає**; hashes/заповнені поля фіксують заявлене походження, а не замінюють кваліфікацію дослідження.

Для дослідження U реалізовано умовне правило `MetricUncertaintyFromUniformEdgeBound(metric,e)`. Якщо для **кожного краю кожного відповідного рядка** доведено sup-bound ±e відносно правильного observable, target точний і відповідність/повнота незмінні, тоді похибка метрики обмежена `k·e`:

| Метрика | k | Підстава |
| --- | --- | --- |
| max absolute two-edge error, pooled P95, row-max P95 | 1 | absolute/max/порядкова статистика 1-ліпшицеві в sup-нормі |
| signed edge-error range, max absolute width error, adjacent edge step | 2 | різниця двох значень з похибкою ≤e |
| width range | 4 | ширина має похибку ≤2e, її range — ≤4e |

Це консервативні межі; спільний зсув може скорочуватися. Функція не оцінює e, не переносить scatter у U і не створює доказу. Для різних residual edge-компонент правило застосовується окремо до кожної доведеної межі, після чого metric-компоненти додаються лінійно. Невідоме e лишається невідомим. Target/capture misregistration поза доведеним scope та caps цим правилом не закриваються.

**Caps поки не мають дозволеного фізичного рішення.** `CompareCapMetric` повертає `Incomplete / cap_evidence_policy_unavailable` для виміряної геометрії та `cap_incomplete` без контуру. Це стосується L∞ Hausdorff, absolute longitudinal error, overshoot й undershoot, незалежно від sampling bound або числового допуску. Повний cap provenance/context та capture/extraction U не реалізовані; додавати довільний scalar U через `CompareMetric` замість них заборонено. `Complete` caps означає лише надану геометрію, не повноту її фізичного доказу.

Геометричний допуск **не дозволяє** overdraw у чужий колір, прозору/заборонену область, вихід за user-selected rect або пропуск потрібного Solid. Колір/покриття мають окремий заздалегідь заморожений raw per-pixel контракт із незмінними RGB12/contrast80 та незалежним підтвердженням кожного заявленого Solid. Half-intensity край і хороша геометрія не встановлюють ці gates.

```text
policy не frozen або немає затвердженої області вимірювання → BLOCKED_POLICY
оцінити всі доступні gates і записати всі причини, без раннього приховування інших відмов
є доведене порушення хоча б одного gate → FAIL; відсутні дані додатково позначити
інакше немає обов'язкового кадру/перерізу/context/uncertainty → INCOMPLETE
усі геометричні gates PASS → GEOMETRY_PASS лише для перевіреного context
geometry + color + coverage + caps/joins/overlap + повна evidence matrix PASS → PHYSICAL_QUALITY_PASS
```

`Operational PASS`, `Target PASS`, `GEOMETRY_PASS`, `PHYSICAL_QUALITY_PASS` і придатність конкретного профілю — окремі вердикти. `completed`, збіг курсора, hash/replay, PASS фікстур або bit-accuracy Q/jitter не замінюють жодного фізичного gate.

## Приймання та стан реалізації

Після оцінки вимірювача фіксуються policy hash, числові межі, analyzer hash, target/context/порядок випадків і незалежний набір приймання, якого не використовували для підбору маршруту. Старі RC-дані — діагностика й регресія, не нове незалежне приймання. Усі обов'язкові повтори мають пройти окремо; середнє не компенсує невдалий випадок. Після зміни кандидата або метрики попередній приймальний набір стає навчальним/діагностичним, потрібен новий untouched set.

Існуючі Test_01_Four_Blocks, Test_02_Edges, Test_03_Caps_Junctions і D-план зберігаються; нової матриці з повторними F6/Alt+Tab для цієї зміни не створено. Фізичні H/V, caps, стики, два кольори та потрібні контексти деталізують у їхніх target-specific annotations перед запуском. Наявність історичного D-плану з незамороженими target pairs не означає готове приймання.

Архітектурна межа: target — `TargetPreparation/Planner`; незмінне фізичне відображення — `Coverage.Partition`; діагностичні edges — `StandardBandResponse`; повний слід/власник кольору — `StandardPaintGeometry/StandardBoundaryLayers`; виконання — `Painter/Native`. Цей документ не змінює жодного з цих модулів.

Реалізовано `MeasureLine`, `MeasureCap`, `CompareMetric` та захищені `CompareLineMetric` / `CompareCapMetric`; [Core-перевірки](../../tests/CanvasForge.Core.Tests/StandardPhysicalQualityChecks.cs) охоплюють зсув, нахил, мінливу ширину, останній рядок, pooled/row P95, пропуски, обидва напрямки, caps та сумісність походження/U. Перерізи не зсуваються й не підганяються під власну пряму. Жоден із цих API не встановлює замороженість політики чи production-придатність.

Для caps приймаються вже надані повні замкнені полілайни. Чисельно рахується Hausdorff для їхніх вершин; результат містить **геометричний інтервал для наданих безперервних полілайнів**, а не видає відстань між вершинами за точну відстань між контурами. Похибка дискретизації обмежена `max(r_target,r_observed)`, де `r` — половина максимальної L∞-довжини сегмента, включно із замикаючим. Ця межа не оцінює похибку виділення фізичного контуру з кадру; вона потребує окремої U. Надто грубі контури можуть лишити приймання INCOMPLETE. Для longitudinal extrema полілайну використовуються вершини, тому sampling-похибка до цієї величини не додається вдруге.

Ресурсні межі реалізації: довжина осі ≤32768 фізичних px, не більш ніж 2048 вершин одного контуру та 4 млн пар вершин; координати скінченні в діапазоні Int32. Невалідні, дубльовані або сторонні перерізи відхиляються, відсутні лишаються в явному списку. Результати `MeasureLine`/`MeasureCap` мають `PhysicalQualityCertified=false` і `ProductionEligible=false`; `CompareMetric` дає лише числовий verdict одного gate.

## Уточнення review0017: nominal RGB і rendered RGB

Відсутній/розірваний рядок nominal RGB12-маски означає невідповідність її колірному критерію, **не доведену відсутність фарби чи геометричну дірку**. Всі10426 рядків цих26 станів мають суцільний contrast80 run. На фінальних ROI median rendered RGB=(38,35,28)/(42,39,33) для requested000000; всі28 зрізів перевірено проти повних native оригіналів. [Аудит і scope](../../../rendered-color-review-20261022/rendered-color-review.json).

Вимір UI palette/swatch підтверджує source selection, а не rendered Canvas color. Локальний `BrushLocalColorProof` містить reference під час вимірювання, але збережений геометричний `BrushFootprint`/`StrokeProfile` не є independent position-bound color map: не має відповідних RGB/absolute area/raw evidence bindings. У frozen settings цієї сесії активних footprint/stroke profiles0, archived geometry profiles15; готової карти rendered RGB немає. Не підставляти archived masks чи UI RGB як незалежну картографію кольору полотна.

Можлива rendered-reference mask — **окрема, ще не реалізована/невалідована ревізія observable**. Вона мусить окремо зберігати Requested/source RGB та calibration-only rendered reference, його position/context/history/scene scope й raw evidence; перевіряти незмінні RGB12/contrast80 на untouched validation. Не підміняти аргумент Requested чинного nominal API відрендереним кольором із after. Reference з іншої тестової смуги лишається діагностикою; різниця двох послідовних смуг не відокремлює вплив позиції від часу/порядку. Без відповідного незалежного reference результат Unavailable, без підвищення tolerance або інтерполяції невиміряних зон.

Ця невирішена кольорова кваліфікація не блокує діагностику вже наявних contrast edges. Фізичне вирівнювання потребує окремого перевіреного відгуку обох країв/історії; сам по собі новий reference не випрямляє штрихи. Код nominal mask/START/емітера в review0017 не змінювався.
