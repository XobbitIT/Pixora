# Живий тест RC7 — Standard / етап A

Збірка: 1.0.14-rc.7+local-rc7-standard. Агент її в Rust не запускав. Цей список не сертифікує Adaptive чи всю матрицю D.

1. На чистому Canvas вибери brush tool і вручну Interval0.01/Opacity1.00. У Standard натисни «Підготувати до малювання». Виділи внутрішню область приблизно біля паперу, перевір запропоновані зелені межі та натисни Enter. Обведи решту запитаних областей. Має вистачити однієї підготовки без тестових крапок/ліній та speed trials. Старий еталон RC6 треба захопити знову; видаляти весь config не потрібно.
2. Намалюй Test_01_Four_Blocks і Test_02_Edges у звичайній палітрі. Потім повтори підготовку й короткий малюнок у HEX на чистому Canvas. Порівняй фактичний результат із тим самим target; 100% означає відправлені команди, не pixel certification.
3. На окремому чернетковому полотні зміни Undo/Redo активність до START і поверни чистий стан. Ця зміна сама по собі не повинна викликати geometry pause. Undo під час готового малювання змінює paint state; його безпечний checkpoint resume цим тестом не доводиться.
4. Перевір F6, alt-tab, вихід/повернення редактора. Під час паузи вибери гумку або піпетку: Pixora не повинна малювати нею. Має або знову підтвердити brush після безпечного застосування, або зупинитися з tool-state reason. Не рухай мишу під час автоматичного вводу. Розмір/DPI/положення вікна зміни — очікується блокування до нового capture, без самовільного перенесення координат.
5. Якщо підготовка чи START блокуються, збережи session/failures/config та папки canvas-captures і editor-diagnostics. У selection.json потрібні bounds/no-go/candidate reasons; при tool failure — tool-state.json/tool-row.png. Не повторюй десятки разів калібрування великих пензлів: зараз перевіряємо A, а не B0/C.

Потрібні нові native paired captures для availability та негативів initial bounds/ROI. Старі відеокадри й синтетичні fixture bounds не замінюють такого доказу. За помилки API курсора не очікується автоматичний retry: ввід зупиняється з явною причиною.
