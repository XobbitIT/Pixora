# Живий тест Pixora 1.0.14-beta.58

1. Розпакуй beta.58 в нову папку. Відкрий чисте полотно Rust. У Pixora вибери звичайну палітру, ліміт 4 кольори та робочий Size 3.
2. Натисни «Підготувати до малювання». Після вибору/відновлення областей повинні виконатися тільки кольори, керування та три незалежні крапки одного пензля. Для палітри один раз захопи активний зразок кольору, якщо програма попросить його. Початкова підготовка не запускає Speed Probe.
3. Перевір, що пензель підтверджений, очисти тестові крапки, відкрий просте двоколірне зображення й натисни «Почати». Перевір результат і фінальні відсотки покриття; 100% команд не означає 100% фарби.
4. Повтори для 8 та 16 кольорів без повторного виділення незмінених областей. Ліміт плану не повинен впливати на знаходження повзунків. Зміна кольорового режиму чи геометрії може вимагати нового виміру.
5. Перейди в HEX, залиш чисте полотно, вибери Size 3. Калібрування повинне підтверджувати джерело кольору до та після кожної крапки. Якщо ядро відхилене, надішли brush-calibration і записи brush_paint_source. Не потрібно обходити відмову.
6. Додатково, на чистому полотні: комбіноване калібрування 3/10/20. Size без ядра не повинен мати активного старого підтвердження після невдалого повторного тесту; інші успішні Size залишаються доступними.
7. Додатково, після успішного Size 20 і просторової перевірки: запусти Speed Probe на полотні ~1039 × 1044 px. Помилка про 62 ділянки 132 × 132 px повинна зникнути. Невдала перевірка прискорення не блокує звичайне малювання.
8. F6 → пауза/продовження, ESC → зупинка. Після скасованого калібрування неповний Size не повинен називатися підтвердженим.

Для аналізу потрібні session-csharp.jsonl, config-csharp.json та папки brush-calibration / controls-diagnostics / speed-probe. Зберігаються в %LOCALAPPDATA%/Pixora. Нові контрольні записи: controls_relocated, brush_paint_source. Не переносити конфіг іншої машини без захоплення її Rust.
