# Pixora 1.0.14-beta.45 — короткий тест ноутбука

1. Закрий стару Pixora й розпакуй beta.45 у нову папку. Відкрий Rust на полотні. Якщо керуєш через віддалений робочий стіл, вимкни синхронізацію буфера обміну на час перевірки. Це усуває можливе стороннє втручання, але лог сам не доводить, що саме воно спричинило помилку.
2. У «Захоплення Rust» перезахопи **Інтервал (Interval)** разом із числом справа. Перевіряй числові поля спочатку окремо; достатньо одного запуску. Під час операції залиш Rust на передньому плані й не копіюй інші дані.
3. Очікувано Size, Interval 0.01 і Opacity 1.00 читаються та підтверджуються. Якщо поле не читається, повідомлення має назвати його. У такому разі зупини тест пензля й надішли новий `session-csharp.jsonl` та `config-csharp.json`; не повторюй десятки калібрувань Size 1.
4. Якщо працюєш у HEX, окремо перевір тестові кольори FF3333 / 12AC5F / 0397E2. Лог має містити однакові `target` і `read`. Якщо HEX не читається, спочатку повтори захоплення його поля.
5. Після успішних controls і HEX відкалібруй **Size 3** на чистій ділянці. Це перший тест фізичного відбитка на цьому ноутбуці; число 3.00 саме по собі його не підтверджує. Перевірка повинна записати діагностику трьох крапок та стабільне ядро.
6. Якщо Size 3 підтвердився, вибери його робочим розміром, вимкни Adaptive й аудит для першого короткого запуску та намалюй чотири кольорові квадрати. Після цього можна окремо перевіряти Size 1 і швидкість. Без підтвердженого Size 1 не очікуй Adaptive або ремонту тонких країв.

Запиши версію у шапці, останнє успішне поле, текст помилки й чи Rust залишався на передньому плані. Відео необов'язкове: нові логи містять координати вводу й поле, яке не читається.
