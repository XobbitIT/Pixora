# Pixora 1.0.14-beta.41 — живий тест

1. Закрий попередню Pixora. Розпакуй увесь новий архів у нову папку. Перевір beta.41 у заголовку. Конфіг видаляти не потрібно. На іншому ПК повтори захоплення Rust.
2. Відкрий чисте полотно, залиш Rust на передньому плані під час перевірок. «Перевірити керування Rust»: Size, Interval 0.01, Opacity 1 — три повні успішні запуски. На ноутбуці це досі обов’язкова жива перевірка transport beta.40.
3. HEX: FF3333, 33FF33, 3333FF — точне читання кожного кольору. Невдалий або неправильний readback не повинен проходити.
4. «Пензель»: Round, Size 3. Можна виконати «Налаштувати та перевірити все». Якщо Size 1 не підтверджений, але Size 3 має ядро, автоматична послідовність має продовжитися для Size 3; форма не повинна переключатися на Square лише через Size 1. Adaptive й ремонт країв залишаються недоступними без базового доказу.
5. На чистому полотні — «Виміряти просторові зміщення». Усі шість контролів мають пройти. У діагностиці видно окрему межу рухомого мазка. FAIL не перетворюється на PASS; при помилці достатньо session-csharp.jsonl і відповідної папки speed-probe.
6. Очисти полотно. Запусти тест швидкості для того самого Size і форми. Кандидати проходять тільки з повним ядром, правильним локальним кольором і трьома повторами плюс запасом. Старі маршрути beta.40 не використовуються. При скасуванні чи втраті фокуса ввід має припинитися.
7. Four Blocks у HEX 64: спочатку без Adaptive й підтверджених швидких маршрутів; потім повтор із новим підтвердженим маршрутом. Перевір суцільність блоків, колір і час. Для аудиту/ремонту спершу потрібна придатна базова маска Size 1.

Зараз не потрібно знову багаторазово калібрувати Size 1: beta.41 прибирає його блокування швидкості інших підтверджених Size, але не змінює вимірювання непрозорого ядра одиночних крапок.
