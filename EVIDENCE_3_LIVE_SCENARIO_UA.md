# Standard Evidence 3 — сценарій одного живого збору

**Сценарій для погодження. До твого підтвердження живий запуск не виконується.**

Мета: зібрати одиничні H/V-штрихи та окремі кадри чорного/білого накладання. Це збір даних, не сертифікація точності й не тест швидкості Max Speed. Великий малюнок повторювати не потрібно.

1. Розпакуй `Pixora_Standard_Evidence_3_Windows_x64.zip` в окрему папку.
2. Відкрий у Rust окреме порожнє полотно. Підготовлене захоплення має бути чинним, розміром щонайменше **900×920 фізичних px**. Твоє останнє захоплення **1044×1043** підходить за розміром. Якщо геометрія та підготовка не змінились, повторне захоплення не потрібне.
3. Переконайся, що підготовлено кольори та Size 3, вибрано круглий пензель. У Rust вручну залиш **Interval 0.01 / Opacity 1.00**. Ці два поля програма не зчитує й не налаштовує. Потрібні точні чорний і білий у захопленій палітрі або підготовлений HEX. На полотні не повинно бути попереднього малюнка/пробних крапок.
4. Закрий звичайне вікно Pixora та запусти **`Collect_Standard_Evidence.cmd`** з нової папки. Протягом **10 секунд** поверни Rust на передній план із відкритим редактором полотна. Не натискай звичайний «Почати».
5. Залиш мишу й клавіатуру без дій до завершення. Програма сама виконає **38 проб** на рознесених ділянках без Undo: 36 одиничних H/V, прямий/зворотний напрямки, довжини 16/64/400 px, по три повтори в різних місцях; потім H- і V-смуги з окремими чорними та білими проходами. F6, ESC, втрата фокуса чи небезпечний інструмент завершують серію як INCOMPLETE; автоматичного продовження немає.
6. Після **DATA_COLLECTED** відкрий нову папку в `Standard_Evidence/<дата-час-id>/`. Збережи її повністю: `protocol.json`, `settings.json`, `series-status.json`, `events.jsonl`, baseline, усі `sample-*`, знімки та gzip-траси. Можна запакувати папку в ZIP для аналізу.
7. Якщо отримано **INCOMPLETE**, збережи ту саму папку з частковими даними та повідомленням. Не запускай повторно ту саму серію й не перероби великий малюнок: спершу аналізуємо вже записаний збій.

Під час збору кожне переміщення надсилається одним пунктом із часовими мітками GetCursorPos. Це навмисно інструментований профіль Rapid/Pitch1/Batch1. Його результати не можна автоматично переносити на Max Speed/великі пакети або інші форми пензля. Повтори рознесені за позиціями; це не B0-оцінка шуму в одній координаті.
