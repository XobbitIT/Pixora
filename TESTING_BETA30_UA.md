# Pixora beta.30 — живий тест калібрування кольору та широкого ядра

1. Закрий попередню Pixora. Розпакуй увесь beta.30 ZIP в окрему папку та запусти Pixora.exe. Перевір 1.0.14-beta.30 у шапці. Збережи старі config і session; калібрування попередньої ревізії має бути застарілим, а Adaptive/залежні швидкі маршрути не повинні вважатися готовими.
2. Відкрий чисте полотно Rust. Не змінюй вікно, масштаб UI, камеру чи освітлення під час тесту. Перевір захоплення керування та точні Size / Interval 0.01 / Opacity 1. Почни запис відео. Не рухай мишу під час автоматичного вводу; ESC скасовує.
3. Форма «3 · Суцільний круглий», розміри «1/3/10/20», HEX Direct: калібруй. Очікуємо три окремі крапки кожного Size. Якщо запитано чорний, світлий слід не має стати підтвердженням. Для сумнівного кадру можлива одна додаткова пауза і знімок, але не повторний мазок поверх крапки.
4. Звір таблицю результатів: 3/3 означає вимірювання, а окремий чіп показує придатність ядра до широкого планування. Вузькі 1×N px мають бути жовтими; наведений у підказці розмір — ядро, не значення Size і не повний фізичний діаметр. Швидкість до нового Speed Probe залишається «не перевірено».
5. Повністю очисти полотно. Обери «4 · Суцільний квадратний», розміри лише «1». Виконай калібрування за тих самих умов. Збережи всі три контрасти та порівняй з Round 1. Провал допускається; не знижуй поріг заради PASS. Без підтвердженого Size 1 Adaptive не має вмикатися.
6. За можливості повтори на чистому Canvas у Palette. Перед цим захопи саме її керування. Світлий обраний колір на темному фоні має перевірятися як освітлення; підтримка кольору не повинна бути обмежена тільки HEX/чорним.
7. Після очищення спробуй «Повторити лише невдалі вибрані Size». Актуальні успішні маски нової ревізії мають зберігатися. Перезапусти Pixora і перемкни UA/EN: стани, причини відмови та підказки широкого ядра мають залишатися зрозумілими й перекладеними.
8. Лише після актуального успішного калібрування відповідного Size виконай Spatial + Speed Probe на чистому полотні. Окремо перевір рух курсора на відео: parking поза ділянкою для screenshot і фінальне повернення до останньої дії. Ця версія не змінює координати parking та не гарантує виправлення фізичних нерівних ліній.

Для аналізу збережи відео, session-csharp.jsonl, config-csharp.json і нові brush-calibration/run-* з before/background/after, suspect-after (якщо є), metrics та result. У metrics важливі requestedColor, colorCheck, initialColorCheck і recaptured. Не малюй повторно на старих тестових крапках.

Спочатку потрібен чесний Round/Square Size 1 A/B. Великий фінальний малюнок, Auto Shape та Size 40/60/100 поки не потрібні. Новий архів пройшов автоматичні перевірки; нових живих тестів гри під час його підготовки не проведено.
