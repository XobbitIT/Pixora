# Pixora 1.0.14-beta.42 — живий тест локального ядра

1. Закрий стару Pixora, розпакуй нову збірку в нову папку. Конфіг не обнуляй. Перевір версію beta.42. Старі маски пензля можуть показуватись як застарілі — це очікувано.
2. Відкрий чисте полотно Rust. Якщо вікно, DPI або layout змінились, повтори захоплення областей. Перевір числові Size / Interval / Opacity та HEX (або палітру).
3. У розділі «Пензель» обери Round, лише Size 3 і «Калібрувати автоматично». Не рухай мишу. Має бути три місця нанесення; у кожне придатне місце програма повернеться рівно один раз для контролю насичення. Це очікуваний цільовий рух, а не випадкове паркування.
4. Відкрий діагностику пензля. Для кожного повтору перевір три знімки й «Насичення: підтверджено», стабільні еталонні px N/N. Локальні RGB різних повторів можуть відрізнятись. Якщо насичення не пройшло, надішли всю папку run-* з brush-calibration, config та session-csharp.jsonl; не повторюй тест поверх тих самих крапок.
5. Очисти полотно й окремо перевір Size 1, потім 10 і 20. Size — значення контролу Rust, не фізичний діаметр. Слабкий Size 1 може лишитись відхиленим; успішний Size 3/10/20 повинен залишитись доступним для свого тесту швидкості.
6. Якщо Round не дає ядра, очисти полотно і перевір Square окремо, лише якщо квадратний пензель дійсно присутній і його ряд правильно захоплено. Не вважай вибір у Pixora доказом вибору в Rust.
7. На чистому полотні для успішного Size 3 запусти шість просторових контролів. Очисти полотно, потім Speed Probe. Повторне калібрування пензля закономірно скасовує старий доказ швидкості.
8. Перевір Four Blocks: спершу звичайний ввід без Adaptive та аудиту; потім підтверджений маршрут. Adaptive і ремонт країв перевіряй лише після підтвердженого Size 1. Порівняй краї, суцільність, кольори й час.
9. Окремо перерви калібрування ESC під час другого нанесення. Має припинитись ввід, не повинні з’явитись новий підтверджений Size або профіль швидкості. Очисти полотно перед наступною спробою.

Важливо: ядро походить лише з першого відбитка. Фізично темніша контрольна крапка не повинна зробити слабкий перший відбиток «суцільним». Старі два знімки не мають доказу насичення. Збережи відео разом із новими логами; якщо тест не пройшов, потрібні всі три повтори та їхні -saturation.png.
