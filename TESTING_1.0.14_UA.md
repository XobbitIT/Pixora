# Тест Pixora beta.11

Розпакуй весь архів beta.11 в окрему папку, запусти Pixora.exe й перевір версію у шапці.

1. У Settings розгорни додаткові налаштування: поля мають стояти рівно в одній колонці на широкому й вузькому вікні. Довгі підписи можуть займати два рядки.
2. Завантаж портретне, квадратне та широке зображення. Перевір, що рамки прилягають до зображення, видно весь малюнок, а на вузькому вікні порівняння може стати вертикальним. Перемкни «Збільшити результат» / «Порівняти».
3. Перемкни English і розгорни Settings: картки, прапорці та числові підписи мають бути англійською.
4. У Speed Probe перевір окремий чіп «Покриття». До нового START він не має бути зеленим «Перевірено», навіть якщо тест швидкості успішний. При вимкненому аудиті показує «Вимкнено».
5. З увімкненим аудитом після успішного малювання очікується «Перевірено», при помилці — «Потребує уваги», при зупинці — «Перервано». Закриття банера помилки не прибирає статус. Після зміни деталізації попереднє підтвердження скидається.

Для повторного тесту аудиту потрібен новий START на чистому Canvas. Приймання вводу у грі та крайове зміщення пензля потребують подальшої перевірки.

# Перевірка інтерфейсу beta.11

1. Розпакуй весь архів beta.11 у нову папку та запусти Pixora.exe. У шапці має бути 1.0.14-beta.11.
2. Розгорни вікно приблизно до 2000 px. Відкрий «Захоплення» та «Налаштування»: картки мають залишатися до 880 px, поля — біля підписів. Повтори на мінімальному вікні.
3. Перевір окремі пункти «Пензель» та «Speed Probe». Колір чіпів у чеклисті й на сторінці Speed Probe має збігатися. Чіп «Покриття» — окремий результат аудиту, а не підтвердження швидкості.
4. На сторінці малювання введи деталізацію 5: має підсвітитися «Швидко · 5 px». Введи 4: має з’явитися «Власне значення». Натисни «Баланс · 3 px»: поле й профіль руху зміняться разом.
5. Завантаж зображення та перемкни «Збільшити результат» / «Порівняти». Перевір вигляд портретного й широкого зображень. До START кнопка STOP має бути сірою.
6. Якщо аудит зупинив малювання, натисни «Показати пропуски» в банері. Порівняй знімки «до», «після» та червоні пропуски. Закрий банер: діагностика залишається в локальній папці. Наступний тест починай новим START на чистому Canvas.

Для фідбеку надішли вигляд широкого/вузького вікна, стан банера й знімок результату. Наведені нижче тести вводу та Speed Probe залишаються актуальними.

# Тест Pixora 1.0.14-beta.11

1. Повністю розпакуй portable-архів beta.11 у нову папку та запусти `Pixora.exe`. У шапці має бути 1.0.14-beta.11.
2. Очисти Canvas, включно з крапками калібрування. Зберігай однакове зображення, деталізацію, пензель та FPS для порівнянь.
3. Малювання → Точні параметри швидкості → **Experimental (8–16 ms)**. Почни з поля **Experimental = 12**. Увімкни максимальну швидкість перенесення та залиш той самий пакет руху, що в попередньому тесті.
4. Потрібен новий **START**: старі checkpoints не підходять. Якщо використовуєш підтверджений Speed Probe, він замінює ручну затримку для перевірених штрихів; вимкни цей маршрут лише на час порівняння ручних затримок.
5. Порівняй 16 → 12 мс на чотирьох квадратах. Якщо заливка прийнятна, повтори на чистому Canvas із **8 мс**. За нових внутрішніх пропусків поверни 12 або 16 мс.
6. Для чистого вимірювання часу один раз вимкни аудит, порівняй реальний час і результат. Потім окремо перевір аудит та дофарбування. Без аудиту 100% означає надіслані команди; вигляд потрібно перевірити самому.
7. Якщо аудит знову зупиняється на крайовому рядку, не вважай це виправленим швидшим вводом. Перевір захоплення Canvas та калібрування. У цій версії автоматичної компенсації зміщення штампа пензля немає.

Надішли скриншот результату, затримку 16/12/8, реальний час, чи працювали audit/adaptive/HEX. Журнал: `%LOCALAPPDATA%/Pixora/session-csharp.jsonl`; нові записи `motion_group` та `coverage_repair_skipped` допоможуть відокремити затримки руху від крайових проблем. PNG діагностики лишаються локальними.

Перевірено 123 Core тести та 25 WPF сценаріїв. Ігровий тест beta.11 ще не виконано.

# Speed Probe та аудит — додаткові сценарії

# Тест Pixora 1.0.14-beta.11 у Rust

## 1. Запуск

Повністю розпакуй `Pixora_1.0.14-beta.11_Windows_x64.zip` в окрему папку й запусти `Pixora.exe`. У шапці має бути **1.0.14-beta.11**. Runtime входить у portable-збірку. Старий checkpoint не підходить — потрібен новий START.

Захопи Canvas та потрібний режим кольорів. Перевір Size / Interval / Opacity: обводь смугу із запасом разом із числом справа. Вибери суцільний круглий або квадратний пензель. У **Пензель** виконай автоматичне калібрування 1 / 3 / 10 / 20, потім очисти Canvas.

## 2. Speed Probe — перший тест

1. Відкрий **Speed Probe**.
2. На чистому Canvas вибери **Size 3**, натисни **Запустити Speed Probe** і підтвердь пробні штрихи.
3. Не рухай мишу та камеру. ESC скасовує; втрата фокусу або F6 переривають тест. Якщо тест перервано, очисти Canvas перед повтором.
4. Потрібно до 62 чистих квадратних ділянок. Мінімальна сторона ділянки 64 px, для широкого пензля більше. Якщо місця бракує, програма пояснить це до вводу.
5. Розгорни **Результати за Size і напрямком**. Там зберігаються метод, вісь, безпечна затримка та випробувана довжина. Відсутній маршрут не пройшов перевірку. Повтори окремо для Size 1, 10 і 20, очищаючи Canvas перед кожним тестом.
6. Після тесту очисти Canvas. Pixora відновлює свої налаштовані Size/Interval/Opacity, якщо Rust лишився у фокусі. Тестовий колір лишається вибраним; початкові ручні значення гри не зчитуються як резервна копія.

Кандидати 32/20/12/8 мс мають по три повтори та додаткові три повтори із запасом. Успішний профіль автоматично вмикає **Використовувати підтверджений маршрут**. Його можна вимкнути для порівняння. Це порівняння затримок серед цих кандидатів, а не математично найвища можлива швидкість чи FPS-вимірювання.

## 3. Малювання із підтвердженим маршрутом

Вибери **Precision**, точні параметри та **Opacity 1**. Почни з чотирьох кольорових квадратів, нового START і вимкненого аудиту. Перевір суцільну заливку всередині, краї й правильність кольорів після завершення. Потім повтори із адаптивним пензлем на великих однорідних ділянках і дрібних деталях.

Зафіксуй реальний час із увімкненим і вимкненим підтвердженим маршрутом на однаковому чистому Canvas. Профіль не змінює деталізацію зображення. Неперевірені Size/осі та короткі штрихи лишаються на звичайному маршруті. Якщо налаштування змінилися, повтори тест або вимкни підтверджений маршрут.

## 4. Аудит і дофарбування

1. У вкладці Speed Probe увімкни **Перевіряти після кожного кольору**. Для першого тесту дофарбування залиш вимкненим.
2. На чистому Canvas виконай новий START для контрастних квадратів. Після кожного кольору очікується перевірка покриття.
3. Якщо аудит зупинився, прочитай кількість пропусків і невизначених пікселів та переглянь локальні PNG. Подібний колір фону, освітлення або рух сцени можуть зробити результат невизначеним; це не підтверджені пропуски.
4. Потім увімкни **Дофарбовувати підтверджені пропуски**, максимум **1** прохід, і повтори на чистому Canvas. Ремонт має залишатися всередині кольорової області. Крайові пропуски можуть вимагати нового тесту/START.
5. Перевір ESC під час руху, дофарбування та аудиту. У звичайному малюванні перевір F6 і повернення фокусу: миша й Shift повинні відпускатися, controls перевірятися повторно.

Аудит не сумісний із RESUME, бо потрібний початковий кадр кольорової групи. Для продовження checkpoint вимкни аудит і перевір сумісність плану; для перевіреної заливки виконай чистий START.

## 5. Стиль і фідбек

Перевір українську й English, вузьке та широке вікно, клавіатурний focus, поля з неправильними числами і підказку біля вимкненого START. Усі Size/Interval/Opacity та форма — у розділі пензля; параметри руху — на малюванні; аудит — у вкладці Speed Probe.

Надішли: скриншот результатів Speed Probe; результат квадратів після завершення; час перенесення; чи був adaptive/HEX/аудит/дофарбування. Журнал `session-csharp.jsonl` містить `speed_probe_trial`, `speed_probe_complete`, `coverage_audit`, `coverage_repair`. Локальні PNG: `%LOCALAPPDATA%/Pixora/speed-probe` та `%LOCALAPPDATA%/Pixora/coverage-audit`. Вони лишаються на комп’ютері та не завантажуються автоматично.
