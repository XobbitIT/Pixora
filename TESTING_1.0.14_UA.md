# Перевірка Pixora 1.0.14-beta.1 у Rust

## Підготовка

1. Закрий попередню Pixora. Збережи копію папки `%LOCALAPPDATA%\Pixora`, щоб мати початковий конфіг і журнали.
2. Повністю розпакуй portable-архів в окрему папку. Запусти `Pixora.exe`; у заголовку має бути `1.0.14-beta.1` і короткий код збірки.
3. Відкрий редактор малювання Rust. Виконай повне захоплення Canvas, палітри та повзунків; для HEX окремо захопи його поле та controls і виконай тест HEX.
4. Почни з невеликого зображення, `Stable`, `Safe`, `Precision`, `Opacity 1`. Використовуй новий START. Після цього переходь до Rapid/адаптивного пензля.

## Сценарії

| № | Дія | Очікуваний результат |
|---|---|---|
| 1 | Звичайний START у Rust Palette, без переміщення вікна | Кольори й штрихи потрапляють на захоплений Canvas; повзунки встановлюються у правильні точки. |
| 2 | Заверши малюнок, очисти Canvas. Перемісти вікно Rust на тому самому моніторі, не змінюй його розмір. Запусти новий START без повторного захоплення | Canvas, кліки палітри та controls зміщуються разом із Rust. |
| 3 | Після переміщення Rust повторно захопи **лише Canvas**, потім START | Решта областей і точки палітри не залишаються у старій позиції. Особливо перевір Quick Colors і Size 1/3/10/20. |
| 4 | Повтори № 2–3 у HEX Direct; натисни тест HEX і тест controls | HEX-поле й окремі HEX-controls працюють у новій позиції. |
| 5 | Калібруй адаптивний пензель на чистому Canvas від 240×240 px; очисти Canvas. Увімкни адаптивний режим, перемісти Rust без зміни DPI/розміру й запусти START | Сумісне вимірювання пензля приймається; широкі штрихи не виходять за межі кольорових областей. |
| 6 | Під час малювання натисни F6. У Rust зміни Size, Interval і Opacity, повернись до редактора й натисни F6 | Pixora відновлює потрібні controls перед продовженням. Перевір товщину та непрозорість перших штрихів після паузи. |
| 7 | Під час малювання перемкнись у іншу програму. Поверни фокус у Rust і натисни F6 | Пауза відпускає кнопку миші; продовження відновлює controls. В іншій програмі немає штрихів чи HEX-вставок. |
| 8 | Зупини ESC після помітного прогресу. Зміни тільки мову або опції preview, натисни RESUME | Ідентифікатор плану залишається сумісним. До 49 дій можуть повторитися через наявний інтервал збереження checkpoint. |
| 9 | За збереженого калібрування зміни розмір вікна; окремо перевір інший DPI/монітор | Якщо DPI або записаний розмір змінився, START відхиляється до першого кліку. Виконай повне захоплення в новій геометрії й новий START. |
| 10 | Під час малювання перемісти/зміни розмір вікна Rust | Перенесення зупиняється із повідомленням про зміну геометрії; кнопка миші відпущена. |
| 11 | Закрий Rust, залиш браузер або Steam зі словом Rust у заголовку. Спробуй START або захоплення | Pixora повідомляє, що вікно Rust не знайдено; керування сторонньому вікну не передається. |
| 12 | Запусти захоплення й скасуй перший вибір області | Збережене калібрування не очищується. Якщо частину кроків майстра вже підтверджено, ці кроки зберігаються. |

Перехід між моніторами з однаковим DPI та незмінним розміром має працювати як переміщення. Внутрішню зміну масштабу UI Rust за незмінних DPI та розміру вікна ця версія не розпізнає; після такого налаштування потрібне нове захоплення.

## Фідбек

Для кожної проблеми надішли номер сценарію, режим Rust Palette/HEX, Stable/Experimental, профіль швидкості, роздільну здатність, масштаб Windows і кількість моніторів. Опиши очікувану та фактичну поведінку, додай фото/скрин результату й відповідний фрагмент `%LOCALAPPDATA%\Pixora\session-csharp.jsonl` або `crash.log`.

Для F6 корисні записи `slider_check`, `slider_check_unverified`, `slider`, `reprime`. Для координат — `session_rebase`; для HEX — `hex_readback`. Вкажи також, чи ввімкнений adaptive brush і чи використовуєш ручні точки Size.

Найцінніший перший фідбек: сценарії **1, 3, 4, 6 і 8**, потім DPI/кілька моніторів.
