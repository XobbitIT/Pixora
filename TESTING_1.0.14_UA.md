# Повторний тест Pixora 1.0.14-beta.7 у Rust

1. Закрий стару Pixora. Розпакуй **весь ZIP** в окрему папку, запусти Pixora.exe й перевір beta.7 у заголовку. Актуальне калібрування можна використати.
2. Очисти Canvas. Завантаж `Pixora_Test_4_Colors.png`. Для першого тесту вимкни адаптивний пензель, обери **Rapid / Stable / Precision / Opacity 1**, затримку Stable **20 мс**. Деталізацію лиши такою самою, як у попередньому тесті.
3. Увімкни **«Максимальна швидкість перенесення»**. У розширених налаштуваннях перевір **«Пакет швидкого руху (1–16)» = 8**. Виконай новий **START**, а не RESUME старого запуску.
4. Очікується чотири заповнені квадрати: червоний, зелений, синій і чорний, з прозорими проміжками. Перевір не лише краї, а й усю середину кожного квадрата. Чотири вертикальні смуги означають, що проблема лишилася.
5. Якщо заливка правильна, очисти Canvas і повтори з адаптивним пензлем. Далі можна порівняти звичайний та швидкий перемикач на одному зображенні з однаковими профілем, деталізацією, кольорами й Size; запиши фактичний час. Max Speed тестуй окремо після успішного Rapid.
6. Якщо є пропуски, повтори чистий START з пакетом **4**, потім **1**, зберігаючи Stable 20 мс. Зафіксуй скриншот після 100%, FPS і параметр пакета.
7. Після успішної заливки перевір F6, ESC → RESUME і HEX Direct. Після зміни пакета або режиму потрібен новий START. Якщо очистив Canvas, також потрібен START з початку.

Журнал `session-csharp.jsonl` у папці даних Pixora показує транспорт руху, розмір пакета, стартовий checkpoint та elapsedSeconds. `complete` на 100% підтверджує виконання команд; результат у Rust перевіряється скриншотом. Локально пройшли 102 Core та 8 WPF перевірок; повтор у грі потрібен для підтвердження виправлення.

# Архівна інструкція beta.6 — для поточної версії використовуй тест beta.7 вище

1. Закрий стару Pixora, розпакуй **весь ZIP** в окрему папку й запусти Pixora.exe. Перевір beta.6 у заголовку. Поточне актуальне калібрування пензля можна використати.
2. Для порівняння візьми те саме зображення, Canvas, кольоровий режим, деталізацію та максимальний Size адаптивного пензля. Почни з Rapid / Stable / Precision / Opacity 1. Перед кожним запуском очисти Canvas.
3. Зроби новий START із вимкненим «⚡ Максимальна швидкість перенесення». Запиши час. Потім увімкни перемикач у «Малювання» → «2. Якість і швидкість» та зроби новий START на чистому Canvas. Не натискай пресет «Макс. швидкість»: він також змінює деталізацію і завадить порівнянню.
4. Перевір суцільність довгих ліній, тонкі краї, кути квадратів, прозорі проміжки й межі різних кольорів. Переконайся, що Size/Interval/Opacity правильні й HEX не зміщується на наступний колір. Повтори в Rust Palette та HEX Direct.
5. Під час швидкого перенесення натисни F6, зміни числа в Rust і віднови F6: програма має перевірити й відновити controls. Перевір ESC → RESUME з тими самими налаштуваннями. Після зміни перемикача або кроку потрібен START.
6. Якщо видно пропуски — «Розширені налаштування» → «Швидкий рух, px за крок» → **128**, далі 64/32. Якщо швидкий ввід чисел не проходить перевірку, вимкни перемикач; журнали покажуть невдале зчитування. Experimental (16 мс) тестуй після успішного Stable.

Для фідбеку потрібні фактичний час обох запусків, FPS Rust, скриншот результату/коротке відео та session-csharp.jsonl з папки даних Pixora. У complete журнал записує elapsedSeconds, у start — режим, крок та кількість рухів. Загальний час включає стартову паузу й перевірки, але не ручні паузи F6.

Локально пройшли 93 Core та 8 WPF перевірок. Фактичне прискорення у грі ще не виміряне.

# Тест Pixora 1.0.14-beta.5 у Rust

## Запуск і точні числа

1. Закрий стару Pixora. Розпакуй весь ZIP в окрему папку й запусти `Pixora.exe`; заголовок має містити `1.0.14-beta.5`.
2. У Rust відкрий редактор картини. Якщо захоплення beta.3 актуальне, його можна використати. Якщо числа чи форми змістилися, повтори налаштування Rust.
3. Для кожного повзунка обведи один повний ряд разом із числом справа та запасом навколо. Перевір зелені рамки, натисни Enter. Ручні Size anchors не потрібні й не використовуються.
4. Спочатку вимкни адаптивний пензель. Вибери `Stable / Safe / Precision / Opacity 1`. У Rust вручну постав Size 20, Interval 0.33, Opacity 0.5.
5. «Захоплення Rust» → «Числові поля Size / Interval / Opacity» → «Перевірити Rust controls». Очікується Size **1**, Interval **0.01**, Opacity **1**. Pixora вводить числа й копіює їх назад для підтвердження. Для Max Speed ціль Size 3.

## Повтор після відео 20:06

Введення Size 1.00, Interval 0.01 та Opacity 1.00 вже підтверджене журналом beta.4. Основна перевірка beta.5 — чи калібрування проходить першу маленьку крапку й вимірює всі чотири розміри. Очисти попередні тестові крапки перед повтором.

## Адаптивний режим — одна кнопка

1. Відкрий **чистий Canvas** в Rust.
2. У Pixora натисни **«Адаптивний режим»** зліва. У секції **1. Підготовка** має бути зелена/позитивна готовність захоплення. Обери суцільний круглий або квадратний пензель.
3. У секції **2. Автоматичне калібрування** натисни **«Калібрувати автоматично»** й підтвердь тест. Програма сама вибере контрастний колір і виконає 1 → 3 → 10 → 20. Не рухай мишу; ESC скасовує.
4. На Canvas мають з’явитися **чотири крапки різних розмірів**. Після повернення статус має бути **«Калібрування актуальне»**, а в «Виміряні розміри пензля» — чотири результати.
5. У секції **3. Адаптивне малювання** перемикач має бути ввімкнений автоматично. Обери максимальний Size **10** для першої спроби, потім порівняй із **20**.
6. **Очисти Canvas**, перейди до малювання, завантаж `Pixora_Test_4_Colors.png` і зроби новий START. Очікуються чотири кольорові квадрати без виходу широких штрихів за межі.
7. Натисни F6, вручну зміни три числа, повернись до редактора й F6. Програма має відновити та перевірити числа перед продовженням.

Зміна Canvas, режиму кольорів або форми має показати потребу повторного калібрування. Переміщення того самого вікна Rust до START підтримується; зміна DPI/розміру вікна потребує нового захоплення.

## Якщо щось не працює

- Зафіксуй, на якому Size зупинилося калібрування, чи з’явилася крапка та чи змінилося число.
- Додай відео саме від натискання «Калібрувати автоматично» до результату.
- Корисні файли: `%LOCALAPPDATA%\Pixora\config-csharp.json`, `session-csharp.jsonl` та `brush-calibration\failed-before.png` / `failed-after.png`, якщо вони створилися.
- У журналі `control_readback` показує скопійоване число, `slider_check` — підтвердження числа й смуги, `brush_measurement` — виміряну крапку.

82 Core тестів і 5 WPF перевірок перевіряють алгоритми та інтерфейс. Реальний результат малювання й прийняття вводу перевіряються окремо у грі.
