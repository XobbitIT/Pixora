# Pixora 1.0.14-beta.6 — швидке перенесення без зміни деталізації

Користувач підтвердив працездатність адаптивного пензля та HEX у beta.5. Beta.6 додає окремий перемикач «⚡ Максимальна швидкість перенесення» в розділі «Малювання» → «2. Якість і швидкість».

- Сумісні штрихи одного кольору й Size об’єднуються в рух із затиснутою мишею: до 16 початкових штрихів, переходи до 32 px. Тонкі переходи проходять лише по вже запланованих центрах; широкі перевіряються з усім зовнішнім радіусом каліброваного пензля. Прозорість, інший колір та зміна Size розривають рух. Для напівпрозорого/несуцільного пензля об’єднання вимкнене.
- Курсор рухається кроками до 256 px із паузою на кожному кінці та повороті. У розширених налаштуваннях можна зменшити крок до 128/64/32 px, якщо Rust пропускає покриття. Межі: 32–512 px.
- Введення чисел і HEX використовує коротші паузи, прив’язані до 16–100 мс інтервалу вводу. Точне зчитування чисел, свіжий маркер Ctrl+C, перевірка смуги та перевірка HEX збережені. Налаштована пауза застосування HEX також збережена. Уже підтверджене число не вводиться повторно, якщо його смуга лишилася на місці; після паузи кеш скидається.
- Перемикач не змінює cell_px, кількість кольорів, профіль швидкості чи калібрування. Автоматичне калібрування 1/3/10/20 завжди використовує попередні Stable-паузи.
- F6, ESC і втрата фокусу переривають рух та відпускають мишу. RESUME зберігає номер об’єднаного руху; зміна швидкого режиму/кроку потребує нового START.
- ETA враховує рухи, введення початкових controls, HEX та зміни Size. Журнал містить fastTransfer, moveSpan, batches, sourceStrokes і elapsedSeconds.

Перевірено: **93 Core тести, 8 WPF перевірок** (Українська/English, 900/1280 px); локальна збірка без попереджень і помилок. Синтетичні оцінки для Rapid / Stable, Canvas 768×768, однакової геометрії:

| Зображення | Рухи: звичайний → швидкий | ETA: звичайний → швидкий |
|---|---:|---:|
| Суцільна заливка | 768 → 48 | 271.32 → 71.32 с |
| Великі кольорові блоки | 1152 → 72 | 300.29 → 89.32 с |
| Дрібні деталі з прозорими отворами | 8160 → 8160 | 681.93 → 540.10 с |

**Це оцінки алгоритму, не виміряний час у Rust.** Нові короткі паузи й інтерполяція швидких рухів потребують ігрового порівняння; для дрібних деталей виграш менший. Перемикач початково вимкнений.

[Інструкція тестування](TESTING_1.0.14_UA.md).

# Pixora 1.0.14-beta.5 — виправлення вимірювання маленької крапки

- У тесті beta.4 о 20:06 Size 1, Interval 0.01 та Opacity 1 успішно ввелися й зчиталися з Rust. Калібрування зупинилося: центральний піксель не змінився, хоча поряд з’явилася крапка 2×2 px.
- Вимірювання шукає найближчий змінений піксель лише в межах ±4 px від кліку, потім аналізує його зв’язну крапку. Сторонні зміни поза цією ділянкою не підходять.
- Зовнішня рамка залишається відносно координати кліку й враховує зсув. Незмінений центр не зараховується як суцільне покриття широкого пензля. Обрізані крапки й відсутній ввід далі відхиляються.
- `brush_measurement` тепер містить `SeedOffset` та `ChangedPixels` для діагностики.
- 82 Core регресії, зокрема штучний приклад зі зсувом маленької крапки, плюс 5 WPF перевірок. Потрібен повтор автоматичного калібрування в Rust для розмірів 1/3/10/20.

[Інструкція тестування](TESTING_1.0.14_UA.md).

# Pixora 1.0.14-beta.4 — числа й окремий адаптивний режим

- **Точний ввід:** Size / Interval / Opacity вводяться прямо в числові поля Rust. Після Enter програма знову копіює фактичне число та перевіряє смугу. Маркер перед Ctrl+C захищає від застарілого буфера обміну. Ручні Size anchors і кліки по шкалі більше не використовуються.
- **Просте калібрування:** одна кнопка запускає вимірювання 1/3/10/20. Pixora сама вибирає інструмент, форму, контрастний колір, Stable, Interval 0.01 та Opacity 1. Розміри встановлюються числами. ESC скасовує тест.
- **Вимірювання:** курсор із прев’ю пензля відводиться від області перед обома знімками. Вимірюється лише зв’язна крапка біля центру; сторонні зміни сцени ігноруються. Якщо крапки немає чи вона обрізана, зберігаються знімки `brush-calibration/failed-before.png` і `failed-after.png` у папці даних Pixora, а помилка називає Size.
- **Окремий розділ:** «Адаптивний режим» у лівому меню. Три секції, статус готовності, вибір круглої/квадратної форми, одна кнопка калібрування, результати вимірювань, перемикач та максимум Size 10/20. Після успіху режим вмикається; сумісні налаштування Precision/Opacity 1 застосовуються автоматично.
- **Перевірки:** 78 Core регресій і 5 WPF перевірок: відсутнє, актуальне й застаріле калібрування, English, можливість вимкнути старе некаліброване налаштування. Інтерфейс перевірено при ширині 900 та 1280 px.

Введення чисел, автоматичний вибір кольору та малювання чотирьох крапок ще потребують перевірки безпосередньо в Rust. [Інструкція](TESTING_1.0.14_UA.md).

# Pixora 1.0.14-beta.3

Автоматичні межі повзунка всередині рамки, яку можна обвести із запасом. Pixel-perfect виділення не потрібне.

## Нове у beta.3

- Детектор шукає по всій виділеній області, а не лише по її центральному рядку. Широка рамка, підпис, порожнє місце та нерівні відступи підтримуються. Частково захоплені сусідні повзунки ігноруються.
- Після виділення Pixora показує доріжку та числове поле зеленими рамками. Enter зберігає знайдені області; можна обвести знову або скасувати ESC. Якщо повного повзунка немає або знайдено кілька, збереження не відбувається й можна повторити виділення.
- У конфіг записуються фактична доріжка й окреме числове поле. Це працює в майстрі налаштування, ручному захопленні та окремому захопленні HEX-controls. Поля правильно переносяться при переміщенні Rust.
- Прибрано початковий зсув на 4 px і перетягування за край, яке в останньому тесті залишало Interval 0.03 замість 0.01. Клік виконується в точку фактичної доріжки. Якщо перевірка не проходить, повторна спроба вводить число через знайдене числове поле. Після кожного способу потрібне підтвердження зі свіжого скриншота; непідтверджене значення зупиняє перенесення.
- Старі калібрування лише доріжки можуть читатися з автоматичним пошуком числового поля. Для першого тесту beta.3 все одно повторно захопи три повзунки новим способом.

## Перевірка beta.3

70 Core-тестів пройшли. Вісім нових регресій охоплюють реальний кадр останнього відео, широкі й нерівні рамки, підписи, часткових сусідів, неоднозначні виділення, обрізані поля, три масштаби та min/partial/max, старі калібрування й перенесення числових полів. WPF Release build: 0 warnings, 0 errors.

Прийом кліку та введення чисел грою потребує повторного практичного тесту. Інструкція — [TESTING_1.0.14_UA.md](TESTING_1.0.14_UA.md). Почни з нового START; checkpoint старої beta може бути несумісним.

## Попередні виправлення beta.2

Виправлення за відеотестом від 03.10.2026: зайві світлі кольори на прозорих PNG, неправильні Size/Interval/Opacity, пропущені кліки та штрихи Experimental і ненадійне введення HEX.

## Нове у beta.2

- Зміна розміру PNG зберігає RGB окремо від alpha. Фільтри враховують прозорість сусідніх пікселів. Біла підкладка більше не перетворюється на кольори для малювання. На тесті з чотирма квадратами й параметрами з відео обидва режими тепер створюють 4 кольорові групи та 504 штрихи; раніше було 15/885 у палітрі та 95/3402 у HEX.
- Повзунки читаються по інтерактивній доріжці без числового поля справа. Зелений текст більше не вважається заповненням. Підтримуються мінімум і максимум; допустима похибка — менше одного пікселя доріжки. Якщо значення неможливо прочитати чи підтвердити після повторних спроб, малювання зупиняється до штрихів.
- Після захоплення зберігається фактична інтерактивна доріжка. Потрібно обвести всю зелену смугу разом із числовим полем; детектор сам відділяє поле. Повторне захоплення Size очищує старі ручні Size anchors. Ручні точки HEX зберігаються в окремому калібруванні HEX.
- Size 1–100 використовує лінійну координату інтерактивної доріжки. Фактичне число у Rust може трохи відрізнятися через округлення координати до пікселя; beta.2 не гарантує точне десятичне значення з текстового поля.
- Усі три повзунки перевіряються незалежно від старого параметра `verify_controls`. Після F6 значення знову читаються й за потреби виправляються. У журналі `verified: true` означає успішну перевірку положення, а не лише виконаний клік.
- Experimental у списку називається «Experimental (захищений)». Збережена назва конфігу `Experimental 1 ms` сумісна. Мінімальний кадр — 16 мс, утримання кнопки для штриха — 40 мс. Кліки, повзунки та HEX мають ті самі захищені затримки, що й Stable. Швидкість може бути нижчою, ніж у старого Experimental.
- Палітра використовує окремі переміщення курсора, натискання та відпускання з паузами. Опційний зразок активного кольору перевіряється після кліку; є повторні спроби. Без зразка клік виконується з надійнішими затримками, але фактичний колір не підтверджується.
- Зразки активного кольору для Rust Palette та HEX зберігаються окремо. Для перевірки палітри захопи зразок у режимі Rust Palette.
- HEX вводиться через клік, Ctrl+A, вставку, Enter і очікування застосування. Читання використовує Ctrl+A/Ctrl+C з повторними спробами; перетягування через сусідні елементи палітри прибрано. За ввімкненої перевірки непідтверджений колір зупиняє перенесення.
- Повідомлення завершення тепер просить перевірити результат у Rust. Лічильник означає виконані команди, а не доказ, що гра відобразила всі штрихи. Помилки калібрування адаптивного пензля перекладено українською.

## Включено з beta.1

- Коректна база координат `(0, 0)` та перенесення всіх захоплених областей при переміщенні Rust до START за незмінного DPI/розміру.
- Захоплення лише Canvas спочатку переносить решту координат, включно з палітрою, HEX та Size anchors.
- Сумісні вимірювання адаптивного пензля переходять у новий контекст; несумісні відхиляються.
- Вікно визначається за процесом RustClient. Зміни DPI/розміру вимагають нового захоплення; зміни геометрії під час малювання зупиняють ввід.
- Мова й опції preview не змінюють ідентифікатор RESUME. Параметри малювання та координати перевіряються.
- Windows CI виконує перевірки ядра перед створенням portable-пакета.

## Перевірка

62 автоматичні перевірки ядра: прозорість, плани обох режимів, сім вирізок реальних повзунків з відео, захищені затримки, координати, F6/RESUME-контракти, калібрування та випадкові плани. Release-збірка WPF компілюється без попереджень і помилок.

Реальний прийом вводу грою ще потребує повторного тесту. [Послідовність перевірки](TESTING_1.0.14_UA.md). Для beta.2 виконай новий START, а не RESUME зі старої версії.
