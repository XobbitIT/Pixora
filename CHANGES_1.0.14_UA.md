# Pixora 1.0.14-beta.1

Перший пакет виправлень для перевірки у Rust після аналізу версії 1.0.13. Основна мета — стабільне калібрування та відновлення керування.

## Виправлення

- Позиція клієнтської області Rust `(0, 0)` тепер є коректною базою координат.
- Після переміщення вікна повторне захоплення лише Canvas спочатку переносить решту збережених координат у нову позицію. Це охоплює звичайну палітру, Quick Colors, HEX, повзунки та ручні точки Size 1/3/10/20.
- Калібрування адаптивного пензля більше не залежить від абсолютної позиції доріжки Size. Сумісні вимірювання зі старим контекстом v1 автоматично переходять у v2; застарілі вимірювання не приймаються.
- START і тести HEX/controls знаходять вікно через процес `RustClient`. Назва браузерної вкладки чи Steam із текстом Rust не підходить для керування.
- DPI зчитується для цільового вікна. Зміна DPI або відомого розміру клієнтської області вимагає нового захоплення. Автоматично множити координати на коефіцієнт DPI без перевірки ігрового інтерфейсу програма більше не буде.
- Перше підтверджене захоплення після зміни DPI/розміру прибирає старі області, палітру й вимірювання пензля. Скасування до першого вибору зберігає попереднє калібрування.
- Після F6 очищується кеш перевірених Size. Якщо положення повзунка не вдається прочитати, його значення повторно встановлюється за захопленою геометрією.
- Зміна мови, згладжування preview, режиму preview чи згортання вікна більше не змінює ідентифікатор плану для RESUME. Координати та параметри малювання продовжують перевірятися.
- Під час вимірювання пензля зміна геометрії чи втрата фокуса зупиняє процедуру перед наступною точкою.
- Windows CI запускає регресійні перевірки ядра перед публікацією; назва архіву береться з фактичної версії.

## Перевірено автоматично

56 перевірок ядра, включно з 13 новими сценаріями координат, міграції та RESUME. Локальна Release-збірка WPF на Windows компілюється без попереджень і помилок.

## Що перевірити у грі

Ігровий ввід, HEX, фізичний розмір пензля, F6 та різні монітори потребують практичної перевірки. Послідовність і очікувані результати наведені в [TESTING_1.0.14_UA.md](TESTING_1.0.14_UA.md).

Для першого тесту виконай новий START. RESUME, створений старішою збіркою, може бути відхилений через нову версію та формат ідентифікатора плану.

Переміщення вікна до START підтримується за незмінного DPI/розміру. Переміщення під час малювання зупиняє перенесення. Старі конфіги без бази координат потребують повного захоплення; старі конфіги без розміру вікна отримають його під час першого запуску/перевірки, тому попередню зміну розміру для них визначити неможливо.
