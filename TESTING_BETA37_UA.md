# Pixora 1.0.14-beta.37 — короткий тест у Rust

1. Закрий стару Pixora, розпакуй beta.37 в окрему папку й запусти `Pixora.exe`. У заголовку має бути beta.37. Налаштування не потрібно скидати; повтори захоплення, тільки якщо змінилося вікно Rust або програма повідомляє про неактуальні координати.
2. Відкрий редактор малювання й очисти полотно. У Pixora вибери Square №4 та калібрування **лише Size 1**. Запиши відео від натискання кнопки до результату; під час крапок не рухай мишу.
3. Перевір, чи Size/Interval/Opacity встановлюються один раз перед трьома крапками, а не перед кожною. Крапки повинні бути на трьох незалежних ділянках. Заміряй загальний час; порівнюємо з приблизно 22 с останнього beta.36 запуску, без обіцянки конкретного прискорення.
4. На сторінці «Пензель» переглянь усі три результати. Для готовності потрібен Size 1 зі стабільним спільним ядром. «Слід виміряно · немає стабільного ядра» означає, що прискорення ще не дозволено. Якщо крапки слабкі, порожні чи зміщені, зупини цей сценарій і відкрий **«Знімки калібрування»**; повторні тести швидкості зараз не потрібні.
5. У діагностиці переключи всі три повтори: видно кадри «до/після», контраст, непрозору площу та фактичні координати курсора. Після перезапуску Pixora знімки мають лишитися доступними. Переключи UA/EN і перевір нові підписи.
6. **Тільки після готового Size 1:** очисти полотно, виконай просторове калібрування; знову очисти полотно й виконай Speed Probe. Зберігаються лише маршрути з трьома кандидатами й трьома пробами із запасом. Якщо підтверджено тільки горизонталь, вертикаль повинна явно показувати звичайний ввід.
7. Після чинного маршруту й чистого полотна намалюй Four Blocks з аудитом. Перевір суцільність усіх чотирьох блоків, кольори, результат аудиту й позицію курсора після завершення.
8. Окремо на чистому полотні перевір ESC під час калібрування: ввід припиняється, неповний Size не отримує підтвердження. Втрата фокусу має перервати вимірювання. Після кожного переривання очисти пробні сліди.

Збережи відео, `session-csharp.jsonl`, `config-csharp.json` і папки останніх запусків `brush-calibration/run-*` та `speed-probe/run-*` із `%LOCALAPPDATA%/Pixora`. Нові події `brush_controls` показують встановлені та повторно використані параметри; `brush_dot_input` — запитану й фактичну позицію на кожній фазі. Не змінюй JSON для отримання PASS.
