# Pixora 1.0.14-beta.51 — живий тест

Розпакуй весь ZIP у нову папку. Запусти Pixora.exe й перевір beta.51 у заголовку. Налаштування не видаляються автоматично; після зміни роздільності, DPI, режиму кольору чи розташування панелей повтори захоплення. Тестуй на полотні, яке можна очистити. ESC — скасувати, F6 — пауза/продовження. Залиш Rust на передньому плані під час вводу.

## 1. Основний шлях та ноутбук

1. Відкрий Testing/Images/Four_Blocks.png. Оригінал і результат мають завантажитися; під час розрахунку видно пояснення біля недоступного START.
2. На слабкому ноутбуці вибери «Повільний ноутбук» прямо у підготовці. Перевір: візуальне підтвердження, Stable, fast_transfer вимкнений. Цей пресет не визначає FPS і не підтверджує точне число Interval/Opacity через буфер.
3. Відкрий чисте полотно й натисни «Підготувати до малювання». Пройди чотири видимі етапи: області, кольори, керування, три відбитки одного Size 3. Speed Probe і Spatial для цього старту не потрібні. Відхилення пензля не повинно ставати зеленим без доказу.
4. Якщо керування не пройшло, натисни «Чому не пройшло керування?». Збережений crop і критерій мають бути видимі. Якщо знімків немає, кнопка недоступна; повторити захоплення можна через статус Rust або окремі налаштування.
5. Очисти тестові сліди. Натисни «Почати» і дочекайся 100% команд. Збережи screenshot до збереження полотна. Чотири блоки мають бути суцільними, без перефарбування сусідніх кольорів. 100% команд не доводить 100% покриття.
6. Повтори короткий запуск у «Палітра Rust», потім у HEX. Зафіксуй обидва результати. Для ноутбука потрібен окремий завершений прогін візуального режиму без успішного числового копіювання.

## 2. Перевірка нового релізу

1. Швидко змінюй деталізацію 1 / 3 / 5 / 8 і кількість HEX-кольорів 64 / 128 / 256. Результат і ETA мають відповідати останньому вибору; розрахунок не зависає. Відкрий інше зображення під час підготовки прев’ю.
2. Перевір статуси «Зображення / Rust / Пензель / Швидкість / Покриття»: клік відкриває відповідний розділ або діагностику. Повтори українською й англійською, у вузькому та широкому вікні.
3. Відкрий Edges.png. Запиши число і відсоток модельних пропусків, відкрий рожеве накладання. Після малювання порівняй його з фактичним результатом. Тонкі деталі, куди пензель фізично не поміщається, не мають отримувати небезпечних команд.
4. Для HEX із пропусками відкрий «Менше кольорів: порівняти плани». Запиши операції, модельні пропуски й вигляд для 64 / 96 / 128 / 256. Застосуй вибраний варіант і перевір синхронізацію контролів.
5. Виміряй Size 3 / 10 / 20, за бажанням Size 1. Увімкни комбіноване малювання лише з актуальними підтвердженими профілями. Порівняй однакову картинку з робочим Size 3: час, фактичні межі кольорів і якість, а не лише число операцій.
6. Перевір STOP, ESC, закриття під час розрахунку й повторний старт. Попереднє прев’ю не має повертатися після нових параметрів. Для перевірки RESUME зберігай незмінні зображення, контекст, маски та налаштування; старий несумісний checkpoint має відхилятися.

## 3. Тривалий прогін, час та ETA

Для одного фото або складної ілюстрації використай однакові зображення, полотно, кольори й підтверджені пензлі. Запиши активний час, паузи, операції, зміну кольорів/controls, аудит і checkpoint із наявної телеметрії. Не додавай вкладений Draw/Input Waits вдруге. Порівняй ETA на 25/50/75% з фактичним залишком до завершення; після warmup ціль — похибка до ±15%, відхилення також є результатом тесту. Короткі плани до 20 операцій оцінюй як попередній розрахунок. Repair і retries познач окремо.

Надішли session-csharp.jsonl, config-csharp.json, скриншоти та пов’язані каталоги діагностики. Для кожного прогону вкажи beta.51, ПК/ноутбук, роздільність/DPI, Rust FPS під час тесту, назву зображення й сценарій. До цього inGameTest=false; новий CI теж ще не запускався.
