## 1. Діагноз поточного планувальника
`Coverage.Expand` рівномірно ділить **екранний прямокутник** на сітку цілі w×h і заповнює кожну клітинку екранними лініями з кроком `pitch`. Rust же фарбує **тексельну сітку ≈511×525**, яку видно трапецією. Звідси три системні вади, жодну з яких не прибирає налаштування швидкості чи зсуву:
1. Межі клітинок цілі не збігаються з межами текселів → рвані краї кольорових ділянок.
2. Вертикальні лінії перетинають нахилені стовпці → сходинки (пояснено й виміряно, 0037/0039).
3. Зайве перефарбування: крок 1–3 px при текселі ≈2 px і штампі ≈2.6 текселя на Size 3.

## 2. Пропозиція: «Тексельний режим» (ціль B, яку користувач прийняв 23.10)
**Core — нові ізольовані модулі (без зміни чинного маршруту):**
- `TexelGrid`: стовпці (боки L/R, N, ψ) + рядки (V2: S, Y∞ з тих самих боків, ψ) + мапування курсора (β, c, β_y, c_y). Явні параметри з provenance, без значень за замовчуванням; відмова поза перевіреним контекстом (view, rect, DPI, Size/Shape).
- `TexelTarget`: ресемплювання зображення на тексельну сітку в межах виділення користувача (exact rect зберігається; ціль у текселях — окреме поле, не прихований recrop).
- `TexelPlanner`: основний напрямок — **горизонтальні прогони вздовж тексельних рядків** (рядки горизонтальні, тож Y курсора = центр рядка, а кінці прогону — центри стовпців). Рядки заповнення через висоту штампа (3 текселі на Size 3). Вертикалі — лише нахилені траси по центру стовпця (як TX), коли потрібні.
- `TexelQualityGate`: 0 неочікуваних переходів H/V і ширина за ціллю в текселях (контракт B), з явно невизначеною U до її дослідження.

**Підготовка (App):**
- Майстер калібрування на початку сесії: кадр паперу → боки/верх/низ (view-policy вже є) → перевірка збігу з попередньою сесією; якщо вид змінився — повторна калібровка або відмова від тексельного режиму.
- Опційна калібрувальна смужка (кілька контрольних штрихів у куті або на запасній табличці) для уточнення фази стовпців, де запас тонкий (0045: розбіжність до 0.16 текселя проти запасу 0.25).

**UI:** прев'ю в текселях (що реально ляже на табличку), вибір розміру картинки в текселях, позначка «експериментальний режим», ETA із нової кількості штрихів.

**Безпека/сумісність:** чинний Standard лишається fallback; RGB12/contrast80/16 ROI/0.985/rect delta 0 і guards не змінюються; режим вмикається лише за явного вибору й успішної калібровки.

## 3. Порядок робіт (кожен крок — окремий заморожений дослід)
1. Об'єднана 2D-модель на вже використаних даних (training-only).
2. Живий тест обох осей: короткі вертикалі/горизонталі в нових місцях + квадрат-заливка по центрах текселів; прогноз індексів обох осей і 0 подій D — до збору.
3. Розмір штампа в текселях для Size 1 / Size 3 / інших форм — визначає ефективну роздільність картинки (на Size 3 мінімальна деталь ≈3 текселі).
4. Кінці штрихів (caps) і стики сусідніх прогонів.
5. Колір: рендерений тон палітри як незалежний еталон (0017/0018).
6. Лише потім — інтеграція в START як експериментальний режим із fallback, далі контракт B → Steam.
