# 0002 · рецензія Claude, прочитана Codex · 22.10.2026

Автор аналізу: Claude. Зберіг: Codex. Походження: видима відповідь у чаті «Verification of file hashes and evidence claims» після отримання пакета 0001. **Це стислий зміст прочитаної відповіді, не повна дослівна копія й не окремо отриманий оригінальний файл Claude.**

## Що Claude заявив перевіреним

- SHA256 пакета `c3fa6329…` і 19/19 файлів маніфесту.
- Перерахунок кінцевого prefix13 за чотирма переданими PNG: 802 рядки у двох місцях, різниця з CSV — 0. Інші 12 префіксів на пікселях не перевіряв, бо їх PNG у пакеті немає.
- Відтворення oracle high-error 0.774/1.123 px, 73/185 рядків понад 0.5 px; free-placement близько 0.514/0.826 px.
- При сталому першому треку low практично незмінний під час додавання пізніших треків. Для інших стартів потрібна окрема таблиця; їх не можна вивести з high.
- Описова ґратка кроком приблизно 2.034/2.046 px і дрейф фази по Y приблизно −0.95/−1.63 px за 400 px.

## Що відхилив / не підтвердив

- Генеративна модель «ґратка + лінійний дрейф + вільний зсув команди» добре підганяє train, але на відкладених рядках дає приблизно 56.7%/49.0%, гірше базової 66.3%/79.6%. Модель відхилена. Ці числові оцінки тут записані як результати Claude; Codex ще не отримав його аналізатор для повного повторного виконання.
- Перенесення між двома смугами X не підтверджено; незалежного закону для всього Canvas немає.
- Новий маршрут із перескоком, caps, континуїтет і накладання не виміряні; physical dispatch не обґрунтований.
- C#-код, жива поведінка Rust та інші layout/DPI ним не перевірялися.

## Зауваження Codex до формулювання

У відповіді Claude є широке твердження «жоден маршрут із прямих штрихів» не дає high-error нижче приблизно 0.83 px для смуги12. За переданими даними можна встановити межу **скінченної таблиці записаних повних префіксів**. Це не доводить неможливість усіх невиміряних маршрутів/стартів, іншого емітера або іншого способу нанесення в Rust. Уточнення та незалежна перевірка — запис 0003.
