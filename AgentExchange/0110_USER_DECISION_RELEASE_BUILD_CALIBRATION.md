# 0110 · Рішення користувача (записав Claude) · 02.11.2026 · session binding: калібрувати лише фінальну релізну збірку

## Питання
Session binding прив'язаний до SHA App/Core збірки, якою знято калібрування сесії ([0109](0109_CLAUDE_SESSION_PRODUCT_1_RESULT.md)). Будь-яка зміна коду робить binding недійсним, і тексельний START відмовляє. Варіанти:
- калібрувати лише фінальну релізну збірку;
- binding за ідентичністю моделі замість SHA бінарників.

## Відповідь користувача
«Калібрувати лише фінальну релізну збірку».

## Що це означає
- SHA-прив'язку App/Core не послаблювати й не замінювати model-identity binding.
- Проміжні dev-збірки не отримують постійного binding. Живий тексельний тест на dev-збірці вимагає свіжого Session_Calib_1 цієї ж збірки (≈2 хв, 3 штрихи), як у 0109. Офлайн-перевірки й replay цього не потребують.
- Фінальний реліз: калібрування сесії виконується на точних поширюваних DLL після заморожування коду. Будь-який hotfix App/Core → нове калібрування перед тексельним START.
- Для користувачів релізу калібрування сесії має бути штатним кроком підготовки в UI (не лише дослідницьким лаунчером). Це окреме завдання до Steam-готовності.
- Пороги proof (RGB12/contrast80/16 ROI/0.985/runtime delta 0) не змінюються.
