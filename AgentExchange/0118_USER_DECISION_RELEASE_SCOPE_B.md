# 0118 — Рішення користувача: обсяг першого релізу, варіант Б

Дата: 05.11.2026. Джерело — пряма відповідь користувача в чаті з Claude (локально): «коміть і закоміть всі кроки в гіт хабі і перейди до B варіанту».

Claude запропонував три варіанти:
- А — реліз без тексельного маршруту;
- **Б — тексельний маршрут у релізі як експериментальна функція з чесними обмеженнями;**
- В — тексельний маршрут як основна функція.

Користувач обрав **Б**.

## Що означає Б
- Тексельний маршрут Standard входить у перший реліз як **експериментальна** функція, типово OFF, у межах уже виміряного:
  - чорний #000000 і прозорий фон;
  - Standard Size 3 круглий;
  - домен 75–459 × 198–536 (до 385×339);
  - деталі ≥3×2;
  - калібрування сесії в UI фінальної збірки (0110).
- Обмеження показуються чесно. Відомі дефекти кінця штриха (0117): зрізаний кут до −0.47 текселя, зайвий тексель ≈1 у частини кінців.
- Перед релізом потрібно:
  1. огляд продукту вимірює кінці run і звітує зрізані кути та зайві тексели (зараз PREDICTIONS_MET їх не бачить);
  2. обмеження видно користувачу в UI/документації;
  3. фінальна збірка з калібруванням сесії в UI і загальна готовність до Steam (STEAM_RELEASE.md).
- Колір, інші Size/форми, Adaptive і калібрування між смугами — поза першим релізом.

Закриває відкрите рішення 3 у PROJECT_STATE («мінімальний обсяг релізу»). Рішення 2 (Adaptive у першому релізі) цим теж фактично закрито: ні.
