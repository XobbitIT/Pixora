# Pixora 1.0.14-beta.49 — тест швидкості та ETA у Rust

Офлайн: 375 Core / 118 WPF перевірок; збірка без warnings/errors. Живий Rust для beta.49 ще не перевірений. Усі дані тесту нижче запише користувач.

1. Розпакуй увесь архів у нову папку. Запусти Pixora.exe з неї та перевір версію beta.49. Збережи попередні журнали для порівняння; не змішуй файли різних тестів.
2. Для перевірки швидкості використай те саме зображення, Canvas і ноутбук зі звіту. Залиши 256 HEX-кольорів, деталізацію, робочий Size 3, форму та параметри вводу такими самими. Полотно має бути чистим. Якщо геометрія, DPI або розмір вікна змінилися, повтори захоплення/калібрування за звичайним порядком.
3. Перевір, що показані H/V маршрути, мс та довжина відповідають підтвердженому Probe. Для старого профілю зі звіту це Size 3, Safe 12 мс, MaxLength 15 px. Не підміняй значення вручну. Не проводь новий Probe для першого порівняння, якщо старий профіль актуальний: інакше зміняться дві речі одночасно.
4. Переконайся, що кількість операцій нового плану збігається з попереднім. В іншому випадку цей запуск може перевірити функціональність, але його час не доводить прискорення виконавця.
5. Почни малювання. Запиши відео або час старту. На 25%, 50% і 75% занотуй прогрес, показаний ETA та поточний час. Після завершення порівняй кожний ETA з фактичним часом, що залишався від цієї точки. Початкові 20 операцій — прогрів оцінки.
6. Перевір, що всі кольори правильні, великі ділянки заповнені, краї та тонкі деталі не стали гіршими. 100% виконання команд саме по собі не підтверджує піксельну точність.
7. Для окремого короткого тесту використай Testing/Images/Four_Blocks.png. Перевір F6 → пауза → продовження, ESC → зупинка → RESUME. ETA не має включати час паузи; продовження має повторно перевірити controls і створити власну модель часу.
8. Збережи session-csharp.jsonl і config-csharp.json після завершення. Для аналізу потрібні `plan`/початок запуску, `eta_update`, `motion_group`, `hex`, `complete` та повідомлення помилок. Нові поля пояснять, який маршрут використовується і де лишилися витрати.

Очікується менша повторна обробка калібрування та ETA з витратами між штрихами. Конкретний виграш загального часу ще не виміряний у грі. Затримки, довжини Probe, кольори та формули малювання залишені тими самими.
