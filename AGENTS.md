# Pixora — постійні правила агента

Оновлено: 29.10.2026. Мета — завершений, перевірений продукт для Steam та подальша підтримка. Максимально використовуй доступні інструменти, самостійно приймай обґрунтовані рішення й доводь узгоджене завдання до перевірного результату. Не підмінюй виконання плануванням, зайвими погодженнями чи косметичними оптимізаціями.

Перед роботою читай [PROJECT_STATE.md](PROJECT_STATE.md). Інші матеріали відкривай за потребою: [архітектура](ARCHITECTURE.md), [перевірки](TEST_MATRIX.md), [реліз](STEAM_RELEASE.md). Старі beta/RC-звіти — історія; джерело правди — поточний код і конкретні докази.

## 10 правил

1. **Завершуй результат.** Відтвори дефект → виправ → перевір → усунь виявлені пов'язані дефекти в межах завдання. Частковий патч, інструмент збору чи зелена збірка самі собою не закривають фізичний дефект. Реальний блокер назви точно; виконай незалежну доступну частину й не заявляй про успіх без доказу.
2. **Спочатку простеж архітектуру.** Перед великими змінами визнач модулі, виклики, залежності, власника стану та сумісність settings/checkpoint/profile. Змінюй найменшу достатню частину; працюючі компоненти не переписуй без доведеної необхідності.
3. **Підтримуй постійну регресію зображень.** Дрібні деталі, великі заливки, alpha/чорний, HEX/palette, тонкі лінії й Adaptive перевіряй за TEST_MATRIX. Порівнюй target, маршрут і фактичний результат відповідними методами. Golden не оновлюй мовчки з результату зміненого алгоритму.
4. **Забезпечуй відкат.** Перед ризиковою зміною збережи перевірний попередній стан/артефакт і відомості про сумісність. Не стирай чужі чи незакомічені зміни, користувацькі дані й тести. Руйнівний Git не є способом виправлення; commit/push виконуються за окремим дорученням.
5. **Вимірюй оптимізацію.** Фіксуй точність, CPU/RAM, час підготовки й малювання, Active/Wall та відмови. Порівнюй до/після на однакових входах і середовищі; зберігай розкид. Швидкість приймається без погіршення якості та STOP/PAUSE. Не оптимізуй другорядне за припущенням.
6. **Зупиняй небезпечний ввід.** Перевіряй втрату фокуса, зависання/недоступність Rust, помилкові координати, DPI/resolution, зміну tool, переривання й cursor/capture API errors. На помилці відпускай утримувані кнопки. Невідомий стан не дозволяє paint-down; пороги proof не послаблюй для PASS. Штатний ввід Windows — без ін'єкцій і читання пам'яті гри.
7. **Перевіряй готовий Release.** Запуск, settings round-trip, recovery, залежності, розпакування/встановлення й чисте Windows-середовище перевіряй, де доступно. Розділяй fakes, replay і фізичний тест Rust. Неперевірений аспект лишається відкритим; preview та completed-команди не сертифікують покриття.
8. **Не повторюй невдалий цикл.** Зберігай гіпотезу, доказ, результат і причину відмови. Наступна спроба має нову технічну підставу. Спочатку використовуй існуючі дані й автоматизацію; новий ручний тест проси лише для конкретної незакритої взаємодії. Не додавай звичні F6/Alt+Tab перевірки до кожного незалежного патча.
9. **Визначай наступний пріоритет.** У погодженому обсязі: критичні баги → стабільність → правильність малювання → продуктивність → UX → Steam. Не додавай сторонні функції. Для вже дозволених дій не вимагай повторного погодження; запитуй лише відсутню інформацію чи авторизацію, без якої справді неможливо продовжити.
10. **Передавай короткий актуальний стан.** Після суттєвих змін онови PROJECT_STATE: результат, точна збірка/артефакт, докази перевірок, незавершене й наступна дія. Запис замінюй актуальним, історію залишай у тематичних звітах. Новий агент продовжує звідси; не перечитує весь архів і не починає заново.

## Делегування та вибір моделей

Погоджено користувачем 29.10.2026. Для Pixora дозволено самостійно делегувати незалежні підзавдання допоміжним агентам і обирати доступну модель за складністю без повторного погодження:

- **Пошук, інвентаризація та прості перевірки:** швидша модель, за наявності `gpt-6-luna`.
- **Реалізація й регресійні тести:** основна модель або `gpt-6.1-sol`; рівень міркування відповідно до складності.
- **Архітектура, фізична модель та незалежна перевірка виправлень:** сильніша модель, за наявності `gpt-6-astra`, або `gpt-6.1-sol` із підвищеним рівнем міркування. Не передавати остаточне рішення про фізичну якість лише швидкій моделі.

Перед делегуванням враховувати актуальну доступність моделей та обмеження інструментів. Якщо потрібна модель недоступна, використовувати придатну доступну без вигаданого перемикання. Для короткого послідовного завдання не створювати агентів лише заради делегування. При неоднозначності чи невдалих простих перевірках передавати підзавдання сильнішій моделі.

Кожному агенту задавати межі роботи, власність файлів і критерії перевірки; не допускати одночасного редагування тих самих файлів. Незалежний рецензент перевіряє первинні дані та код, а головний агент перевіряє результати й відповідає за інтеграцію. Вибір моделей не надає нових дозволів на Rust-ввід, commit/push або обмін з Claude. Модель головного чату користувач обирає окремо; це правило стосується допоміжних агентів.

Для погодженої спільної роботи з Claude читай нові записи [журналу обміну](AgentExchange/README.md) та його INDEX. Відокремлюй авторство, спостережену доставку, переказ і незалежно повторений результат; сам файл не означає доступ іншого агента.

Пиши стисло; питання, дублюючі звіти й альтернативні архіви створюй лише за потреби. Не обіцяй фонової роботи без механізму виконання. Ці правила не є підтвердженням готовності: готовність визначається виконаними критеріями та доказами.
